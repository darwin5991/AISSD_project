# 누산기·후처리 검증 명세서

> **2026-11-10 명세 개정:** MAC 입력·가중치 레지스터 1단을 추가해 데이터·valid 경로를 3단으로 변경했다. MAC·Control RTL과 검증환경 코드를 3단 명세에 맞게 수정했고 새 검증 데이터·헤더 5종을 생성했다. 생성기 내부 검사는 PASS했지만 새 RTL의 테스트·시뮬레이션·합성·배치배선은 아직 실행하지 않았다. [변경 범위와 일정](../mac_input_pipeline.md)을 따른다. 기존 실행 기록은 이전 구조의 이력으로 보존한다.

출처: [RTL 검증 계획](../verification.md). 공통 규칙과 해당 모듈의 검증 항목을 원문에서 옮겼다. 이후 사용자가 확정한 사항을 반영하며, 나머지 미정 사항은 확정하지 않는다.

## 1. 검증 방식

**사용자 확정 범위: 공통 검증 규칙과 함께, 5절의 누산기·후처리 정상 시나리오 및 전용 검증 환경을 적용한다.** 이번에 정하지 않은 경계·예외 동작과 추가 검증 범위는 8절에 남긴다.

- 모듈별로 TB, tester, 데이터 헤더를 한 세트로 구성한다.
- Python에서 테스트 입력과 기대 출력을 미리 계산하고 파일로 생성한다.
- Tester는 생성된 입력을 공급하고 기대값과 비교한다. RTL과 같은 연산을 다시 구현해 정답을 계산하지 않는다.
- 데이터 출력뿐 아니라 valid, 주소, enable, busy, done 등 해당 모듈의 모든 출력 포트를 검증 대상으로 둔다.
- 순차 출력과 조합 출력을 구분해 값과 변화 시점을 확인한다.
- 시점 판단은 명세를 따른다. 기준 모델은 명세에서 작성하고, DUT의 실제 출력을 기대값으로 사용하지 않는다.

참고한 deit_fpga의 단위 TB는 TB와 tester를 분리하고, tester에서 자동 생성된 `<module>_tb_data.vh`를 include한다. 참고 프로젝트의 Top TB는 tester 역할을 TB 내부에 포함하지만, AISSD에서는 Top도 TB와 tester를 분리하는 구성을 따른다.

사용자가 지정한 `deit_fpga/tb/`에서 다음 소스를 읽고 구조를 확인했다. 참고 프로젝트의 시뮬레이션은 실행하지 않았다.

- `tb_mac_array/tb_mac_array.v`, `mac_array_tester.v`, `mac_array_tb_data.vh`: TB의 클럭·reset·DUT/tester 연결·timeout, tester의 데이터 헤더 include·parameter 일치 검사·하강 에지 비교 후 입력 공급·오류 집계·PASS/FAIL 출력을 확인했다.
- `tb_sm_rowsum_acc/tb_sm_rowsum_acc.v`, `sm_rowsum_acc_tester.v`: TB와 tester 분리, valid와 데이터를 함께 비교하는 구성을 확인했다. 이 tester의 `#2` 중간 시점 추가 검사는 AISSD에 적용하지 않으며, 확정한 하강 에지 비교 방식을 따른다.
- `tb_vt_top/tb_vt_top.v`: Top TB 내부에 입력 공급·비교 역할이 함께 있는 구성을 확인했다. AISSD의 Top은 기존 확정대로 TB와 tester를 분리한다.

참고 소스의 reset 극성·유지 길이·데이터와 모듈 구조는 그대로 옮기지 않는다. AISSD에서 확정한 reset·수치 형식·실제 MNIST 데이터·모듈 구성을 따른다.

## 2. 파일 역할과 구성

| 파일 | 담당 역할 |
| --- | --- |
| `tb_<module>.sv` | 클럭·리셋, DUT·tester 인스턴스와 신호 연결, 전체 timeout |
| `<module>_tester.sv` | 입력 공급, 출력 비교, 검사·오류 수 집계, 불일치 로그와 PASS/FAIL |
| `<module>_tb_data.vh` | 입력·기대 출력·비교 마스크 배열, 벡터 수와 실제 생성 설정 |
| `<module>_golden.py` | 입력 생성, 독립 기준 계산, 클럭별 상태 추적과 데이터 헤더 출력 |

모듈별 TB·tester·데이터 헤더 세 파일을 같은 TB 폴더에 둔다.

**사용자 확정: `05_tb/`의 분류는 `04_rtl/`의 구성을 따른다.** `common/`, `mac_array/`, `accumulator_postprocess/`, `memory/`, `controller/`로 구분한다. Top과 Control unit은 해당 RTL과 같이 `controller/`에 둔다.

**사용자 확정: Python golden 생성기는 `03_model/golden/`에 모아 두고, 실제 사용하는 `.vh` 파일은 해당 TB·tester와 함께 둔다.**

```text
project/05_tb/accumulator_postprocess/
├── tb_accumulator_postprocess.sv
├── accumulator_postprocess_tester.sv
└── accumulator_postprocess_tb_data.vh

project/03_model/golden/accumulator_postprocess_golden.py
```

데이터 헤더에는 자동 생성 파일임을 표시하며 Python을 통해 갱신한다. 수동으로 기대값을 고쳐 RTL에 맞추지 않는다. 생성기 파일명은 위 패턴을 기준으로 하고, 공통 출력 형식과 보조 함수는 재사용할 수 있다.

## 3. Python이 생성할 데이터

| 데이터 | 내용 |
| --- | --- |
| 입력 벡터 | 각 단계에서 tester가 DUT에 공급할 데이터·설정·제어 값 |
| 기대 출력 | 명세와 동일한 정수 연산 및 상태 전이로 계산한 모든 출력 |
| 비교 시점 | 각 하강 에지의 입력 변경 전 비교 시점과 출력별 클럭 지연을 명시 |
| 비교 마스크 | 명세상 값이 정의되지 않은 출력·비트에 한해 비교 제외 범위 명시 |
| 생성 정보 | 벡터 수, 폭·parameter, 소수 비트·shift, 사용한 seed 등 재현 정보 |

Signed 값은 폭에 맞는 2의 보수 비트 패턴으로 저장한다. 배열 포트의 lane 순서와 32비트 워드의 첫 바이트 [7:0] 배치를 명시한다.

**사용자 확정: 최초 Top 검증은 MNIST test 이미지 0번(sample ID = 0) 한 장으로 수행하며, 대부분의 시뮬레이션 시나리오는 해당 이미지의 실제 추론 데이터를 사용한다.** 중간 모듈 검증도 같은 추론 과정에서 발생하는 실제 연산 입력과 중간 결과를 사용하며, 무작위 데이터를 기본 검증 입력으로 사용하지 않는다.

**사용자 확정: 최초 시나리오는 정상 추론 1회로 한다.** 초기화 → start → FC1 → FC2 → FC3 → ARGMAX → done을 검증한다. 실행 중 추가 start와 재실행 등 예외 시나리오는 최초 검증에 포함하지 않는다.

실제 데이터는 Python 기준 모델에서 생성한다. RTL의 출력을 기대값으로 사용하지 않는다. 동일 이미지의 입력·weight·bias·부분합·누산값·레이어별 출력을 모듈별 검증에 활용하고, 제어 신호의 기대값은 명세의 실행 일정에 따라 독립적으로 계산한다.

**사용자 확정: 무작위 데이터가 필요한 경우 seed는 42를 사용하고 기록한다.** 이번 최초 검증은 이미지 0번의 정상 흐름으로 한정하며 별도 무작위·경계·예외 사례를 추가하지 않는다. 전체 재현 범위와 벡터 수는 4.1절 및 5.1절을 따른다.

같은 이미지의 실제 bias·부분합을 입력으로 사용하고, 해당 연산의 누산값과 후처리된 레이어 출력을 기대값으로 사용한다.

`valid=0`이라는 이유만으로 데이터 출력을 모두 비교에서 제외하지 않는다. 명세상 값이 정해지는 출력은 계속 비교한다. 비교 마스크는 미구현 동작이나 불일치를 숨기는 용도로 사용하지 않는다.

## 4. 입력 공급과 비교 시점

**사용자 확정: TB 클럭 주기는 10 ns(100 MHz)로 한다.**

**사용자 확정: 시뮬레이션 시간 단위는 1 ns, 시간 정밀도는 1 ps로 한다.**

클럭·리셋은 TB에서 발생시키며, Python 기준 모델도 같은 reset 조건과 초기 상태를 사용한다.

**사용자 확정: Reset은 비동기 active-low이며, 시뮬레이션 시작 시 3주기(30 ns) 동안 유지한 뒤 클럭 하강 에지에서 해제한다.**

**사용자 확정: 레지스터 출력과 조합 출력을 포함한 모든 출력은 클럭 하강 에지에서 기대값과 비교한다.** 출력 비교를 위해 별도 1 ns 지연을 두지 않는다.

입력 공급과 비교는 다음 순서로 진행한다.

1. 클럭 하강 에지에서 현재까지 유지한 입력과 내부 상태에 대한 모든 출력을 기대값과 비교한다.
2. 비교를 마친 뒤 다음 벡터의 입력·설정·제어 값을 공급한다. 해당 값은 다음 하강 에지의 비교를 마칠 때까지 유지한다.
3. 다음 상승 에지에서 DUT가 입력을 처리한다.
4. 다음 하강 에지에서 출력별로 명세에 정해진 클럭 지연을 반영한 기대값과 비교하고, 같은 순서로 반복한다.
5. 마지막 입력 뒤에도 필요한 파이프라인 지연만큼 검사를 이어가 마지막 결과까지 비교한다.

같은 하강 에지에서 새 입력 공급과 출력 비교를 수행할 때는 반드시 비교를 먼저 한다. 새 입력에 대한 조합 출력을 입력 변경과 동시에 비교하지 않는다. 별도의 클럭이 없는 조합 하위 모듈도 TB 클럭의 하강 에지를 비교 기준으로 사용한다.

**사용자 설계 방향: 큰 모듈은 내부 중간 레지스터가 있는 순차 경로를 사용한다.** 중간 레지스터 뒤의 조합 후처리는 허용하며, 출력단이 조합회로라는 이유만으로 추가 출력 레지스터를 요구하지 않는다.

출력별 순차·조합 여부와 클럭 지연은 각 모듈 명세를 따른다. Python 기준 모델도 같은 하강 에지에서 비교할 값을 생성한다.

### 4.1. 첫 벡터와 마지막 비교

**사용자 확정: 클럭 초기값은 0이며, reset은 30 ns 하강 에지에서 해제하고 첫 비교·입력 공급은 40 ns 하강 에지에서 수행한다.** 첫 비교에서는 reset 이후 초기 출력을 확인하고, 비교를 마친 뒤 해당 시점의 Top 입력 흐름을 공급한다. 최초 입력·설정은 Python 기준 모델의 reset 상태와 실제 Top의 LUT·메모리·MAC 흐름에 맞춘다.

**사용자 확정: 마지막 Top 입력을 공급한 뒤 다음 하강 에지까지 한 번 더 비교한다.** 입력 i는 공급 후 다음 상승 에지에서 처리되고 하강 에지 i+1에서 비교한다. 후처리 뒤에 출력 레지스터를 추가하지 않으며, MAC의 3단 마무리를 그대로 적용하지 않는다. 누산기 자체의 마지막 1클럭 비교 규칙은 유지하고, 입력을 만드는 Top·MAC 일정만 개정한다.

Top 재현 시점 수를 T라고 하면 벡터 0~T-1에서 해당 입력을 공급하고, 벡터 T에서 마지막 입력의 처리 결과를 비교한 뒤 종료한다. 마지막 비교 뒤에는 새 검증 입력이나 별도 대기를 추가하지 않는다.

## 5. 모듈별 검증 항목

아래는 의존 관계에 따른 권장 순서다. 실제 구현 시작 모듈과 세부 사례는 해당 작업을 시작할 때 정한다.

| 단계 | 대상 | 주요 검증 항목 |
| --- | --- | --- |
| 4 | 누산기·후처리 | bias 초기화, 누산, 결과 저장, 다음 bias와 동시 처리, 조합 후처리 |

하위 모듈도 각자의 입력·출력을 직접 검증하는 공통 방향은 유지한다. 이번 전용 TB는 아래 범위에 따라 누산기·후처리의 외부 출력만 비교하며, 하위 모듈 개별 TB의 작성 범위와 일정은 이번에 정하지 않는다.

### 5.1. 단독 검증 범위와 전체 재현 구간

**사용자 확정: 이미지 0번의 FC1~FC3 전체와 FC3 더미 출력 2개를 포함하고, Top 초기화부터 최종 메모리 읽기까지 전체 흐름을 재현한다.** 추론 구간만 잘라 사용하거나 묶음 사이 공백·레이어 전환을 압축하지 않는다.

| 구간 | 누산기·후처리에 재현할 흐름 |
| --- | --- |
| Reset 및 초기화 쓰기 | Reset으로 누산·결과 레지스터가 0이 된 상태와 실제 Top의 입력·설정 |
| 초기화 확인용 전체 읽기 | TB 읽기에 따른 bias 읽기값 및 MAC 부분합 변화. 유효 누산이 없는 동안의 출력도 비교 |
| FC1~FC3 | 실제 bias·부분합, bias 적재·유효 누산·결과 저장 일정, 묶음 간 중첩 및 레이어 설정 전환 |
| ARGMAX·완료 | 누산·결과 상태 유지와 실제 LUT 설정 변화 |
| 최종 A/B 전체 읽기 | Memory·MAC 흐름에 따른 입력 변화 및 비활성 제어 상태 |
| 마지막 비교 | 마지막 Top 입력을 처리한 뒤 다음 하강 에지의 외부 출력 |

FC1은 128묶음 × 196회, FC2는 32묶음 × 128회, FC3는 3묶음 × 32회의 유효 부분합을 누산한다. 명세상 유효 누산 이벤트는 총 29,280회이며, bias 적재와 결과 저장은 각각 163회다. 이는 전체 TB 벡터 수와 구분한다.

기본 범위는 정상 추론 1회다. 정상 일정에 포함된 공백·동시 결과 저장과 다음 bias 적재·레이어 전환은 포함하되, 임의 공백·실행 중 추가 start·재실행·별도 경계 및 예외 사례는 추가하지 않는다.

### 5.2. 입력 벡터와 Python 기준 함수 재사용

**사용자 확정: 기존 Control·Memory·MAC의 Python 기준 함수를 재사용해 전체 입력 흐름을 구성한다.** 실제 Control·Memory·MAC RTL을 전용 TB에 연결하거나 RTL의 관측값으로 벡터를 만들지 않는다. Tester가 준비된 입력 벡터를 DUT에 직접 공급한다.

| 입력 | 형식 | 구성 기준 |
| --- | --- | --- |
| bias_load, result_load | 각각 1비트 | 명세에서 도출한 Control 기준 일정 |
| bias_data[0:3] | signed 8비트 × 4 | Memory 기준 모델의 bias 읽기 출력. 첫 바이트 [7:0]이 lane 0 |
| bias_shift | signed 6비트 | 실제 Top의 현재 LUT 설정 |
| partial_sum[0:3] | signed 32비트 × 4 | 실제 Top 피연산자 흐름을 반영한 MAC Python 기준 출력 |
| psum_valid | 1비트 | MAC 데이터와 동일한 3단 유효 표시 경로의 출력 |
| relu_en | 1비트 | 실제 Top의 현재 LUT 설정 |
| output_shift | unsigned 5비트 | 실제 Top의 현재 LUT 설정 |

clk·rst_n은 TB가 공통 규칙대로 공급한다. Bias의 1클럭 BRAM 읽기 지연과 MAC 부분합·valid의 3단 경로를 반영하고, 누산기는 해당 상승 에지 직전에 보이는 입력을 샘플링한다.

**사용자 확정: 비활성 구간에도 bias·부분합을 실제 Top에 보이는 흐름대로 재현한다.** 비활성이라는 이유로 일괄 0 또는 직전 값으로 바꾸지 않는다. 메모리 읽기 출력의 유지·갱신, 버퍼 선택 변경, MAC의 매 클럭 데이터 갱신을 반영한다.

Control 단독 검증에서 비교 제외된 설정값이나 주소의 자리표시자를 실제 Top의 입력값으로 그대로 사용하지 않는다. 특히 현재 LUT는 ARGMAX 준비부터 bias_shift=0, output_shift=0, relu_en=0을 출력한다. 이 설정과 완료 이후 흐름까지 보완한다. 이는 이번 정상 Top 재현의 구체적인 입력값이며, 미정 경계 동작을 새로 정의하는 것은 아니다.

### 5.3. 독립 계산과 기존 연산 정답 대조

**사용자 확정: Python 생성기가 기존 bias8·psum32 데이터를 바탕으로 명세의 클럭별 상태와 출력을 계산하고, 저장된 bias32·acc32·레이어 출력과 대조한다.** 저장된 최종 출력만 각 클럭에 복사하는 방식으로 대체하지 않는다.

- 원본 bias8을 32비트로 부호 확장한 뒤 bias_shift로 정렬하고 저장된 bias32와 대조한다.
- 전체 입력 흐름에서 유효 부분합이 원본 psum32의 묶음·입력 워드·lane 순서와 일치하는지 대조한다.
- bias 적재와 각 유효 부분합 누산 후 상태를 계산하고, 원본 acc32의 초기 단계 및 각 누산 단계와 대조한다.
- 각 레이어의 완료 결과에 ReLU → 산술 우측 shift → signed 8비트 포화를 적용하고 저장된 레이어 출력과 대조한다.
- 계산한 상태와 유지 중인 후처리 설정으로 각 하강 에지의 output_data 기대값을 만든다. 기존 정답 대조와 RTL 출력 비교는 구분한다.

| 상승 에지의 조건 | Python 기준 상태 갱신 |
| --- | --- |
| bias_load=1, psum_valid=0 | 정렬된 bias를 누산 상태에 적재 |
| bias_load=0, psum_valid=1 | 기존 누산 상태에 lane별 부분합을 더함 |
| bias_load=0, psum_valid=0 | 누산 상태 유지 |
| result_load=1 | 해당 상승 에지 직전 누산 상태를 별도 결과 상태에 복사 |
| result_load=0 | 결과 상태 유지 |

결과 저장과 다음 bias 적재가 겹치면 이전 누산값을 결과 상태에 보관하고 누산 상태에는 다음 bias를 적재한다. 결과 저장은 같은 에지에 갱신되는 새 누산값을 사용하지 않는다. bias_load와 psum_valid의 동시 활성 우선순위는 정의하지 않으며 이번 정상 시나리오에서 발생시키지 않는다.

후처리는 조합회로다. 결과 상태가 유지돼도 relu_en·output_shift가 변경되면 출력 기대값을 다시 계산한다. 레이어 전환에서는 이전 레이어의 마지막 쓰기가 끝난 뒤 설정을 변경하고, ARGMAX 준비 이후의 shift=0·ReLU 비활성도 반영한다.

이 계산과 원본 정답 대조는 Python 생성기의 역할이다. Tester는 헤더의 입력을 공급하고 미리 저장된 외부 출력 기대값을 비교하며, 내부 누산 연산이나 후처리를 다시 구현해 정답을 계산하지 않는다.

### 5.4. 외부 출력 비교 범위

**사용자 확정: 전용 TB에서는 외부 output_data만 비교한다.** acc32·result32 등 DUT 내부 상태를 계층 경로로 관측하거나 강제로 변경하지 않는다. 문제가 발생하면 내부값 비교의 범위와 방법을 별도로 논의한다.

output_data는 32비트 워드 전체를 비교하고, lane 0~3은 각각 [7:0]·[15:8]·[23:16]·[31:24]에 대응한다. 비교 신호 수는 1개다.

Reset 이후 초기 상태, 누산 중 이전 결과 유지, 결과 저장, 다음 bias 적재와의 중첩, 레이어 설정 변경, ARGMAX·완료·최종 읽기 및 마지막 비교까지 외부 출력을 계속 비교한다. psum_valid=0 또는 result_load=0이라는 이유로 출력을 제외하지 않는다.

### 5.5. 헤더 배열과 비교 마스크

**사용자 확정: 입력은 제어·설정 신호별 배열과 bias_data·partial_sum의 lane별 배열로 구성한다.** 각 배열의 같은 인덱스는 같은 하강 에지 벡터를 뜻한다.

- 기대 출력은 output_data의 32비트 배열 1개로 저장한다.
- 비교 마스크는 output_data에 대한 벡터별 1비트 배열 1개로 저장한다.
- 이번 정상 흐름의 마스크는 모두 1이며, 벡터마다 워드 전체를 비교한다.
- 기대값은 해당 하강 에지에서 새 입력을 공급하기 전의 출력이다. 입력 i의 상승 에지 처리 결과와 유지한 후처리 설정은 비교 i+1에 반영한다.
- Signed 입력은 폭에 맞는 2의 보수 비트 패턴으로 저장한다.
- 헤더에는 형식 버전·sample ID·신호 폭·벡터 수·시간 설정·단계 경계·예상 사이클·timeout 및 원본·생성 실행 식별 정보를 남긴다.

## 6. 수치·메모리 기준

- 입력·weight·bias·레이어 출력은 signed 8비트다.
- 곱셈·adder tree·부분합·누산·결과 레지스터는 signed 32비트다.
- Bias는 부호 확장 후 shift로 정렬하고 누산기의 초깃값으로 사용한다.
- 출력 변환은 산술 우측 shift로 하위 비트를 버린 뒤 -128~127 포화다.
- FC1·FC2는 ReLU를 적용하고 FC3는 적용하지 않는다.
- 초기 F와 shift는 명세의 확정값을 사용한다. 오프라인 입력·weight·bias의 nearest-even 변환과 RTL 출력의 비트 버림을 구분한다.

기존 [generate_golden.py](../../03_model/generate_golden.py)는 이미지 한 장의 BRAM 초기화 데이터, 레이어별 출력·부분합·누산 정답을 생성한다. 이 데이터는 연산 정답이며 클럭별 출력 벡터 자체는 아니다. 모듈별 생성기에서 재사용할 때 입력 공급 순서와 지연을 반영해 `.vh`로 변환한다.

## 7. 판정과 기록

### 공통 실행 환경

- **사용자 확정: 시뮬레이터는 xsim을 사용한다.**
- 기본 검증 결과는 tester의 자동 비교와 텍스트 로그로 확인한다.
- **사용자 확정: 파형 확인은 사용자가 별도로 요청한 경우에만 수행한다.** 파형 수동 확인을 기본 검증 절차나 PASS 판정의 필수 조건으로 두지 않는다.
- **사용자 확정: 기본 실행에서는 파형을 기록하지 않는다.** 파형 기록·확인은 사용자가 별도로 요청한 경우에만 설정한다.
- **사용자 확정: 데이터 생성기와 xsim은 분리해서 각각 수동 실행한다.** 생성기를 먼저 실행해 사용할 입력·기대값·데이터 헤더를 모두 준비하고, 이후 별도의 시뮬레이션 실행 스크립트를 실행한다.
- 시뮬레이션 실행 스크립트는 미리 생성한 데이터를 사용하며, 데이터 생성기를 자동 호출하거나 데이터를 자동 재생성하지 않는다.
- 생성 데이터의 설정 불일치는 기존 규칙대로 오류로 처리한다. 데이터가 누락된 경우에도 자동 생성하지 않고 준비 오류로 알린다.
- **사용자 확정: 시뮬레이션 실행 스크립트는 Python으로 작성하며, 한 번의 실행에서는 한 모듈만 검증한다.** 사용자가 검증할 모듈을 직접 골라 실행한다.
- 공통 실행기는 90_scripts/run.py이며, 90_scripts/sim_targets.json의 accumulator_postprocess 타깃을 선택한다. 현재 타깃은 기본 등록 상태이며, 전용 TB·tester·헤더 및 타깃 설정의 구체화는 후속 코드 작성 범위다.
- **사용자 확정: 전체 통합 검증은 Top 모듈의 TB·tester로 수행한다.** 모든 모듈 테스트를 한꺼번에 순회하는 실행 방식은 사용하지 않는다.

**사용자 확정: Timeout은 Python에서 계산한 예상 실행 사이클 수에 100클럭의 여유를 더한 값으로 한다.**

- 정의된 출력은 비트 단위로 비교한다. `!==` 비교로 예상하지 않은 X/Z도 불일치로 검출한다.
- 선언 폭·parameter와 생성 데이터의 설정이 다르면 검사를 진행하지 않고 오류로 처리한다.
- Timeout, 불일치, 벡터 누락 또는 실제 비교 없이 종료한 경우 PASS로 처리하지 않는다.
- 오류가 없고 예정된 검사를 모두 완료했을 때 PASS로 판정한다.
- 불일치 로그에는 모듈명, 벡터 번호·시점, 신호명, 실제값과 기대값을 남긴다. 배열 출력은 lane도 식별한다.
- **사용자 확정: 기본 로그는 불일치 상세와 최종 요약으로 한다.** 최종 요약에는 검사 수·오류 수와 PASS/FAIL을 남긴다. 정상 일치한 벡터의 값을 매번 출력하지 않는다.
- 생성 설정과 데이터 출처, 실행 도구·결과를 재현할 수 있게 기록한다. 실제 파일 위치와 실행 명령은 구현 시 정한다.

### 불일치 처리와 개별 모듈 실행

- **사용자 확정: 첫 불일치에서 해당 모듈의 실행을 중단한다.** 모듈명, 벡터 번호·시점, 신호명, 실제값·기대값을 기록하고 FAIL로 남긴다. 배열 출력은 lane도 식별한다.
- **사용자 확정: 실패 확인 후 어떤 모듈을 실행할지는 사용자가 직접 판단한다.** 실행 스크립트는 실패한 모듈에서 다른 모듈로 자동 이동하지 않는다.
- 검증하고 싶은 모듈만 직접 실행하고, 건너뛸 모듈은 실행하지 않는 방식으로 모듈 단위 선택·제외를 수행한다. 개별 테스트 케이스 선택·제외와 전체 모듈 일괄 실행은 현재 지원 범위에 포함하지 않는다.
- 다른 모듈을 실행하더라도 기존 실패 기록은 FAIL로 유지한다. 실행하지 않은 모듈을 검증 완료나 PASS로 처리하지 않는다.
- 기대값 변경이나 비교 마스크 확대로 불일치를 숨기지 않는다. 선택한 모듈에서는 정의된 출력을 계속 비교한다.

컴파일·계층 전개 통과와 기능 검증 PASS를 구분한다. 누산기·후처리 RTL은 구조와 배선이 있고 전용 연산 하위 RTL의 동작은 아직 미구현이다. 공통 signed_adder32와 register_en은 구현돼 있다. 전용 golden 생성기·TB·tester·데이터 헤더는 아직 준비되지 않았으며, 이 문서의 확정은 코드 작성이나 데이터 생성·실행·검증 완료를 의미하지 않는다. 기존 Top 검증은 누산기·후처리가 임시 모델인 구성으로 PASS했으므로 rtl_verified=false다. 기존 Python 정확도나 golden 생성 성공도 RTL 기능 검증 결과로 간주하지 않는다.

## 8. 남은 구체화

- 정상 추론 밖의 추가 경계·예외 사례와 parameter 조합. 음수 bias shift, shift 극값, 포화 경계 등의 별도 검증 범위는 이번에 확정하지 않는다.
- 범위 밖 입력·32비트 오버플로 동작과 bias_load·psum_valid 동시 활성의 우선순위. 이번 정상 시나리오의 기대값을 넘어 임의로 정의하지 않는다.
- 문제가 발생했을 때 추가할 내부값 관측·비교 방식과 하위 모듈 개별 TB의 범위·일정.
- 후속 작업의 진행 시점. 문서 반영, 코드 작성, 데이터 생성, 빌드·테스트·검증, 커밋은 각각 사용자의 요청 범위에 따라 진행한다.

기본 데이터 범위·전체 재현·외부 출력 비교·배열 및 마스크·타이밍·원본 지정과 결과 보존은 위 확정 사항을 따른다. 전용 생성기와 TB·tester 작성, 공통 실행기 타깃 구체화 및 실행은 아직 남아 있다.

미정 동작은 기대값을 임의로 확정해 생성하지 않는다. 해당 사항을 정한 뒤 생성기와 tester에 함께 반영한다.

개정 3단 MAC에 맞춘 전체 Top 재현 시점은 T=265,018이다. 초기화·읽기 응답 규칙과 비교 범위·마스크 정책은 유지하며, 지연·단계 경계·예상 길이는 [개정 일정](../mac_input_pipeline.md)에 따른다. 생성기·tester·실행 타깃 코드와 실제 RTL은 개정했고 새 헤더를 생성했다. 생성 검사 외 테스트·RTL 시뮬레이션은 미실행이므로 기존 PASS를 새 명세의 검증 결과로 사용하지 않는다.
