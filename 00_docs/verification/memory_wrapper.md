# Memory wrapper 검증 명세서

출처: [RTL 검증 계획](../verification.md). 공통 규칙과 해당 모듈의 검증 항목을 원문에서 옮겼다. 이후 사용자가 확정한 사항을 반영하며, 나머지 미정 사항은 확정하지 않는다.

## 1. 검증 방식

이 문서는 공통 검증 환경과 사용자가 확정한 Memory wrapper 단독 검증 범위를 함께 기록한다. 검증 범위·비교 규칙의 확정과 코드 작성·실행 승인은 구분한다.

- 모듈별로 TB, tester, 데이터 헤더를 한 세트로 구성한다.
- Python에서 테스트 입력과 기대 출력을 미리 계산하고 파일로 생성한다.
- Tester는 생성된 입력을 공급하고 기대값과 비교한다. RTL과 같은 연산을 다시 구현해 정답을 계산하지 않는다.
- 데이터 출력뿐 아니라 valid, 주소, enable, busy, done 등 해당 모듈의 모든 출력 포트를 검증 대상으로 둔다.
- 순차 출력과 조합 출력을 구분해 값과 변화 시점을 확인한다.
- 시점 판단은 명세를 따른다. 기준 모델은 명세에서 작성하고, DUT의 실제 출력을 기대값으로 사용하지 않는다.

참고한 deit_fpga의 단위 TB는 TB와 tester를 분리하고, tester에서 자동 생성된 `<module>_tb_data.vh`를 include한다. 참고 프로젝트의 Top TB는 tester 역할을 TB 내부에 포함하지만, AISSD에서는 Top도 TB와 tester를 분리하는 구성을 따른다.

사용자가 지정한 `deit_fpga/tb/`에서 다음 소스를 읽고 구조를 확인했다. 참고 프로젝트의 시뮬레이션은 실행하지 않았다.

- `tb_mac_array/tb_mac_array.v`, `mac_array_tester.v`, `mac_array_tb_data.vh`: TB의 클럭·reset·DUT/tester 연결·timeout, tester의 데이터 헤더 include·parameter 일치 검사·하강 에지 비교 후 입력 공급·오류 집계·PASS/FAIL 출력을 확인했다.
- `tb_sm_rowsum_acc/tb_sm_rowsum_acc.v`, `sm_rowsum_acc_tester.v`: TB와 tester 분리, valid와 데이터를 함께 비교하는 구성을 확인했다. 이 tester의 `#2` 중간 시점 추가 검사는 AISSD에 적용하지 않으며, 확정한 하강 에지 비교 방식을 따른다.
- `tb_vt_top/tb_vt_top.v`: Top TB 내부에 입력 공급·비교 역할이 함께 있는 구성을 확인했다. AISSD의 Top은 기존 확정대로 TB와 tester를 분리한다.

참고 소스의 reset 극성·유지 길이·데이터와 모듈 구조는 그대로 옮기지 않는다. AISSD에서 확정한 reset·수치 형식·실제 MNIST 데이터·모듈 구성을 따른다.

## 2. 파일 역할과 구성

| 파일 | 담당 역할 |
| --- | --- |
| `tb_<module>.sv` | 클럭·리셋, DUT·tester 인스턴스와 신호 연결, 전체 timeout |
| `<module>_tester.sv` | 입력 공급, 출력 비교, 검사·오류 수 집계, 불일치 로그와 PASS/FAIL |
| `<module>_tb_data.vh` | 입력·기대 출력·비교 마스크 배열, 벡터 수와 실제 생성 설정 |
| `<module>_golden.py` | 입력 생성, 독립 기준 계산, 클럭별 상태 추적과 데이터 헤더 출력 |

모듈별 TB·tester·데이터 헤더 세 파일을 같은 TB 폴더에 둔다.

**사용자 확정: `05_tb/`의 분류는 `04_rtl/`의 구성을 따른다.** `common/`, `mac_array/`, `accumulator_postprocess/`, `memory/`, `controller/`로 구분한다. Top과 Control unit은 해당 RTL과 같이 `controller/`에 둔다.

**사용자 확정: Python golden 생성기는 `03_model/golden/`에 모아 두고, 실제 사용하는 `.vh` 파일은 해당 TB·tester와 함께 둔다.**

```text
project/05_tb/memory/
├── tb_memory_wrapper.sv
├── memory_wrapper_tester.sv
└── memory_wrapper_tb_data.vh

project/03_model/golden/memory_wrapper_golden.py
```

데이터 헤더에는 자동 생성 파일임을 표시하며 Python을 통해 갱신한다. 수동으로 기대값을 고쳐 RTL에 맞추지 않는다. 생성기 파일명은 위 패턴을 기준으로 하고, 공통 출력 형식과 보조 함수는 재사용할 수 있다.

## 3. Python이 생성할 데이터

| 데이터 | 내용 |
| --- | --- |
| 입력 벡터 | 각 단계에서 tester가 DUT에 공급할 데이터·설정·제어 값 |
| 기대 출력 | 명세와 동일한 정수 연산 및 상태 전이로 계산한 모든 출력 |
| 비교 시점 | 각 하강 에지의 입력 변경 전 비교 시점과 출력별 클럭 지연을 명시 |
| 비교 마스크 | 명세상 값이 정의되지 않은 출력·비트에 한해 비교 제외 범위 명시 |
| 생성 정보 | 벡터 수, 폭·parameter, 소수 비트·shift, 사용한 seed 등 재현 정보 |

Signed 값은 폭에 맞는 2의 보수 비트 패턴으로 저장한다. 배열 포트의 lane 순서와 32비트 워드의 첫 바이트 [7:0] 배치를 명시한다.

**사용자 확정: 최초 Top 검증은 MNIST test 이미지 0번(sample ID = 0) 한 장으로 수행하며, 대부분의 시뮬레이션 시나리오는 해당 이미지의 실제 추론 데이터를 사용한다.** 중간 모듈 검증도 같은 추론 과정에서 발생하는 실제 연산 입력과 중간 결과를 사용하며, 무작위 데이터를 기본 검증 입력으로 사용하지 않는다.

**사용자 확정: 최초 시나리오는 정상 추론 1회의 메모리 접근 전체로 한다.** 전체 초기화·읽기 확인 → FC1 → FC2 → FC3 → ARGMAX용 읽기 → 최종 버퍼 확인을 수행한다. Memory wrapper에는 `start`·`done` 포트가 없으므로, tester가 `busy`와 메모리 접근 신호를 직접 공급한다. 실행 중 추가 start와 재실행 등 예외 시나리오는 최초 검증에 포함하지 않는다.

실제 데이터는 Python 기준 모델에서 생성한다. RTL의 출력을 기대값으로 사용하지 않는다. 동일 이미지의 입력·weight·bias·부분합·누산값·레이어별 출력을 모듈별 검증에 활용하고, 제어 신호의 기대값은 명세의 실행 일정에 따라 독립적으로 계산한다.

**사용자 확정: 무작위 데이터가 필요한 경우 seed는 42를 사용하고 기록한다.** 최초 Memory 검증은 이미지 0번의 기존 golden 데이터를 사용하며 무작위 데이터를 추가하지 않는다. 기본 검증의 벡터 수는 확정한 메모리 접근 흐름에 따라 계산한다. 정상 흐름 외의 추가 사례는 별도 논의 대상으로 남긴다.

같은 이미지의 입력·weight·bias와 레이어 출력 데이터를 사용해 메모리 초기화·읽기·쓰기·bank 및 A/B 버퍼 접근을 검증한다.

`valid=0`이라는 이유만으로 데이터 출력을 모두 비교에서 제외하지 않는다. 명세상 값이 정해지는 출력은 계속 비교한다. 비교 마스크는 미구현 동작이나 불일치를 숨기는 용도로 사용하지 않는다.

## 4. 입력 공급과 비교 시점

**사용자 확정: TB 클럭 주기는 10 ns(100 MHz)로 한다.**

**사용자 확정: 시뮬레이션 시간 단위는 1 ns, 시간 정밀도는 1 ps로 한다.**

클럭·리셋은 TB에서 발생시키며, Python 기준 모델도 같은 reset 조건과 초기 상태를 사용한다.

**사용자 확정: Reset은 비동기 active-low이며, 시뮬레이션 시작 시 3주기(30 ns) 동안 유지한 뒤 클럭 하강 에지에서 해제한다.**

**사용자 확정: 레지스터 출력과 조합 출력을 포함한 모든 출력은 클럭 하강 에지에서 기대값과 비교한다.** 출력 비교를 위해 별도 1 ns 지연을 두지 않는다.

입력 공급과 비교는 다음 순서로 진행한다.

1. 클럭 하강 에지에서 현재까지 유지한 입력과 내부 상태에 대한 모든 출력을 기대값과 비교한다.
2. 비교를 마친 뒤 다음 벡터의 입력·설정·제어 값을 공급한다. 해당 값은 다음 하강 에지의 비교를 마칠 때까지 유지한다.
3. 다음 상승 에지에서 DUT가 입력을 처리한다.
4. 다음 하강 에지에서 출력별로 명세에 정해진 클럭 지연을 반영한 기대값과 비교하고, 같은 순서로 반복한다.
5. 마지막 입력 뒤에도 필요한 파이프라인 지연만큼 검사를 이어가 마지막 결과까지 비교한다.

같은 하강 에지에서 새 입력 공급과 출력 비교를 수행할 때는 반드시 비교를 먼저 한다. 새 입력에 대한 조합 출력을 입력 변경과 동시에 비교하지 않는다. 별도의 클럭이 없는 조합 하위 모듈도 TB 클럭의 하강 에지를 비교 기준으로 사용한다.

**사용자 설계 방향: 큰 모듈은 내부 중간 레지스터가 있는 순차 경로를 사용한다.** 중간 레지스터 뒤의 조합 후처리는 허용하며, 출력단이 조합회로라는 이유만으로 추가 출력 레지스터를 요구하지 않는다.

출력별 순차·조합 여부와 클럭 지연은 각 모듈 명세를 따른다. Python 기준 모델도 같은 하강 에지에서 비교할 값을 생성한다.

## 5. 모듈별 검증 항목

아래는 의존 관계에 따른 권장 순서다. 실제 구현 시작 모듈과 세부 사례는 해당 작업을 시작할 때 정한다.

| 단계 | 대상 | 주요 검증 항목 |
| --- | --- | --- |
| 5 | RAM·Memory wrapper | 초기화·읽기·쓰기·주소·bank·핑퐁·TB 접근 선택 |

하위 모듈도 각자의 입력·출력을 직접 검증한다. 상위 검증에서는 같은 하위 모듈이 연결된 결과와 전체 시점 관계를 확인한다.

### 5.1. 단독 검증 범위와 제어 입력

**사용자 확정: Memory wrapper 단독 검증에서는 Python이 명세에 따라 만든 일정으로 tester가 제어 입력을 직접 공급한다.** 실제 Control RTL을 단독 TB에 연결하지 않는다.

- 기존 이미지 0번 golden의 입력·weight·bias·레이어별 출력·최종 버퍼 데이터를 사용한다.
- Python 기준 모델은 메모리별 저장 내용과 읽기 출력 레지스터를 독립적으로 추적해 기대값을 만든다. DUT의 출력이나 내부 상태를 기대값으로 사용하지 않는다.
- FC1~FC3의 출력 쓰기 데이터는 기존 레이어 golden에서 공급한다. Memory 단독 검증에서 MAC·누산·후처리 연산을 수행하지 않는다.
- 주소·enable·버퍼 전환·쓰기 시점은 명세의 정상 추론 일정을 따른다. 레이어 전환 때 reset을 다시 주지 않는다.
- 메모리 저장 내용의 초기화·확인은 외부 TB 포트로 수행한다. 계층 경로로 내부 메모리를 직접 읽거나 쓰지 않는다.

실제 Control RTL과의 연결은 후속 Top 검증에서 확인한다. 기존 Top의 Memory 임시 모델을 실제 Memory RTL로 교체하고, MAC·누산기는 임시 모델을 유지한 구성을 사용할 수 있다. 이 검증과 전체 실제 RTL 통합 검증은 구분한다.

### 5.2. 입력 벡터 구성

각 벡터에는 tester가 공급할 입력, 비교 시점의 기대 출력, 비교 마스크를 포함한다. 클럭·reset은 기존 공통 규칙대로 TB가 공급한다.

| 입력 구분 | 신호 | 공급 내용 |
| --- | --- | --- |
| TB 접근 | `tb_en`, `tb_we`, `tb_addr`, `tb_wdata` | 초기화 쓰기·전체 읽기·최종 버퍼 읽기. 주소는 20비트 바이트 주소, 데이터는 32비트 |
| 접근 경로·버퍼 선택 | `busy`, `buf_sel` | TB 구간은 `busy=0`, 내부 접근 구간은 `busy=1`. FC1·FC3는 A 읽기/B 쓰기, FC2는 B 읽기/A 쓰기 |
| 내부 입력 읽기 | `in_en`, `in_addr` | FC 입력 및 ARGMAX용 워드 읽기. 주소는 8비트 워드 주소 |
| 내부 출력 쓰기 | `out_we`, `out_addr`, `out_data` | 레이어별 golden 출력 워드 기록. 주소는 7비트 워드 주소 |
| 가중치 읽기 | `weight_en`, `weight_addr` | 4개 bank의 공통 읽기. 주소는 15비트 워드 주소 |
| Bias 읽기 | `bias_en`, `bias_addr` | 출력 묶음별 bias 읽기. 주소는 8비트 워드 주소 |

`busy=1` 구간에는 `tb_en=0`을 유지한다. 외부 접근은 사용 중인 메모리 영역의 논리 깊이 이내인 4바이트 정렬 주소만 사용한다. 초기화하지 않은 주소는 읽지 않는다. 미사용 영역·범위 밖·비정렬 주소와 정상 흐름 밖의 동시 요청 동작을 임의로 정의하지 않는다.

### 5.3. 신호별 기대값과 비교 마스크

**사용자 확정: 이전 하강 에지에 입력을 공급하고, 상승 에지 처리 후 다음 하강 에지에서 기대값을 비교한다.** 해당 하강 에지의 비교를 모두 마친 뒤 다음 입력을 공급한다.

| 출력 | 기대값 | 비교 구간 |
| --- | --- | --- |
| `tb_rdata` | TB 읽기에서 요청한 메모리·주소의 저장값 | TB 읽기 요청의 1클럭 지연 응답에서만 비교. 응답 외 구간은 마스크로 제외 |
| `in_data` | `buf_sel`로 선택한 A/B의 읽기 출력 레지스터 값 | 값이 정의되는 모든 구간. 읽기 후 유지 구간과 버퍼 선택 변경도 반영 |
| `weight_data[0:3]` | 각 bank의 읽기 출력 레지스터 값 | 각 bank를 비교하며, 읽기 후 유지 구간도 포함 |
| `bias_data` | Bias 메모리의 읽기 출력 레지스터 값 | 읽기 후 유지 구간도 포함 |

기준 모델과 tester는 다음 규칙을 따른다.

- 읽기 출력 레지스터는 reset으로 0이 되지만, 메모리 저장 내용이 모두 0이라고 가정하지 않는다.
- 선택된 접근 경로에서 읽기를 수행한 BRAM의 출력 레지스터만 해당 주소의 저장값으로 갱신한다.
- 접근 없음·쓰기에서는 해당 BRAM의 읽기 출력 레지스터를 유지한다. 쓰기는 저장 내용만 변경하며 읽기 출력을 새 쓰기 데이터로 바꾸지 않는다.
- TB 경로의 읽기도 해당 BRAM의 읽기 출력 레지스터에 반영한다. 내부 출력이 TB 접근 구간 내내 유지된다고 가정하지 않는다.
- `buf_sel` 변경 시 `in_data`는 새로 선택한 버퍼의 읽기 출력 레지스터 값을 따른다. `in_en=0`이어도 선택 변경으로 `in_data`가 달라질 수 있다.
- enable이 0이라는 이유로 정의된 데이터 출력을 비교에서 제외하지 않는다. 비교 마스크로 미구현 동작이나 불일치를 숨기지 않는다.

### 5.4. 확정한 6단계 검증 흐름

| 단계 | 입력·접근 흐름 | 확인 항목 |
| --- | --- | --- |
| 1. Reset | 비동기 active-low reset을 시작 시 3주기(30 ns) 유지하고 하강 에지에서 해제. Reset 중 `tb_en=0` | 읽기 출력 레지스터의 0 초기화. 저장 내용은 초기화된 것으로 간주하지 않음 |
| 2. 전체 초기화 | `busy=0`에서 TB 포트로 A 196 + B 128 + weight 4×29,280 + bias 163 = **117,607워드** 기록 | 기존 이미지 0번 초기화 데이터를 모든 논리 주소에 공급. B의 초기 0도 TB가 명시적으로 기록 |
| 3. 초기화 전체 읽기 | `busy=0`에서 기록한 **117,607워드 전체**를 TB 포트로 읽기 | 주소 해석·bank 선택·저장값과 각 읽기의 1클럭 응답 비교 |
| 4. FC1~FC3 접근 | `busy=1`에서 명세 일정대로 입력·weight·bias 읽기 및 golden 출력 쓰기를 재현 | FC1 A→B, FC2 B→A, FC3 A→B 전환. 서로 다른 버퍼의 읽기·쓰기 중첩과 출력 유지 |
| 5. ARGMAX용 읽기 | `busy=1`, `buf_sel=1`에서 B의 최종 출력 3워드를 명세 일정대로 읽기 | 읽기 응답과 한 워드의 여러 바이트를 처리하는 대기 구간의 출력 유지. argmax 계산은 수행하지 않음 |
| 6. 최종 버퍼 확인 | `busy=0`에서 A 196 + B 128 = **324워드 전체**를 TB 포트로 읽기 | 최종 golden과 비교. FC2의 A 앞 32워드·FC3의 B 앞 3워드 덮어쓰기 및 나머지 영역 유지 포함 |

최초 시나리오는 위 정상 흐름 전체로 한다. 정상 흐름에 포함된 출력 유지·정상 경계 주소는 비교하되, 별도의 경계·예외 사례는 추가하지 않는다. FC3의 더미 2개도 메모리 저장값과 최종 읽기 비교에 포함한다.

마지막 읽기 요청의 응답까지 비교하도록 마무리 벡터를 포함한다. 전체 벡터 수와 예상 종료 사이클은 이 흐름을 구체적인 벡터로 변환하면서 계산하고, timeout에는 기존 규칙대로 100클럭의 여유를 더한다.

### 5.5. 데이터 헤더의 신호별 배열 형식

**사용자 확정: 기존 Control·Top과 같이 입력·기대 출력·비교 마스크를 신호별 배열로 저장한다.** 각 배열의 인덱스는 같은 하강 에지의 벡터 번호를 뜻한다. 기대값은 해당 벡터의 새 입력을 공급하기 전의 출력이며, 같은 인덱스의 새 입력에 대한 즉시 결과가 아니다.

- 입력 배열은 5.2절의 tester 공급 신호별로 구성한다. `clk`와 `rst_n`은 TB가 생성한다.
- 기대값은 `tb_rdata`, `in_data`, `bias_data` 및 `weight_data`의 bank 0~3을 각각 구분한다. 총 7개 32비트 출력값을 비교한다.
- **사용자 확정: 비교 마스크는 출력별·벡터별 1비트로 둔다.** 1이면 해당 32비트 출력 전체를 비교하고, 0이면 해당 출력을 비교에서 제외한다. Weight는 bank별로 기대값과 마스크를 둔다.
- 포트 폭과 배열의 lane·bank 순서를 명시한다. 마스크 적용 구간은 5.3절을 따르며, 마스크가 0인 위치의 저장값은 비교 기준을 뜻하지 않는다.
- 헤더에는 형식 버전, sample ID, 벡터 수, 시간 설정, 예상 실행 사이클·timeout, 원본 실행 및 생성 실행 식별 정보를 기록한다.

### 5.6. 첫 벡터와 종료 타이밍

**사용자 확정: 기존 Top의 단계 일정과 벡터 타이밍을 유지한다.** Memory 단독 검증을 위해 별도의 대기·단계 전환 일정을 새로 만들지 않는다. 명세의 묶음 사이 공백·레이어 준비·ARGMAX 대기는 그대로 재현한다.

| 시점 | 동작 |
| --- | --- |
| 0 ns | 클럭 초기값 0, `rst_n=0`으로 시작 |
| 30 ns 하강 에지 | 3주기 reset 유지 후 해제 |
| 40 ns 하강 에지 | 벡터 0의 초기 출력 비교 후 첫 TB 초기화 쓰기 입력 공급 |
| 45 ns 상승 에지 | 첫 TB 초기화 쓰기 수행 |
| 50 ns 하강 에지부터 | 직전 입력의 처리 결과 비교 후 다음 입력 공급을 매 주기 반복 |
| 마지막 최종 버퍼 읽기 이후 하강 에지 | 마지막 읽기의 1클럭 응답을 포함해 예정된 모든 출력 비교를 마친 뒤 종료 |

Reset 해제 후 첫 비교까지의 대기는 1주기이며, 첫 벡터는 시뮬레이션 시작 기준 4번째 주기의 하강 에지다. TB 읽기 입력을 하강 에지에서 공급하면 다음 상승 에지에서 읽기를 수행하고, 그다음 하강 에지에서 해당 응답을 비교한다.

최종 버퍼의 마지막 읽기 응답을 검사하는 마무리 벡터까지 포함해 전체 벡터 수와 예상 종료 사이클을 계산한다. 마지막 비교 뒤에 별도의 추가 대기를 넣지 않는다. 예상 실행 사이클은 시작 시 reset·대기·마지막 검사까지 포함하며, timeout은 예상 실행 사이클 + 100클럭으로 한다.

### 5.9. 작성한 TB·tester와 실행 타깃

[tb_memory_wrapper.sv](../../05_tb/memory/tb_memory_wrapper.sv)는 클럭·reset, 실제 Memory DUT와 tester의 포트 연결 및 전체 timeout을 담당한다. 실제 Control RTL이나 Memory 임시 모델을 연결하지 않는다.

[memory_wrapper_tester.sv](../../05_tb/memory/memory_wrapper_tester.sv)는 기존 생성 헤더를 include하고 다음 동작을 수행하도록 작성했다.

- 헤더 형식·sample ID·시간·단계별 길이·포트 폭·bank 수와 입력의 X/Z를 확인한다.
- TB 응답 마스크의 1클럭 지연과 모든 내부 읽기 출력의 비교 포함 여부를 확인한다. 데이터 기대값은 Python 헤더에서 가져오며 tester 안에 RAM 기준 모델을 구현하지 않는다.
- 각 하강 에지에서 7개 출력의 비교를 마친 뒤 15개 제어·데이터 입력을 공급한다. `busy`도 tester의 출력이다.
- `!==`로 데이터와 X/Z 불일치를 검출하고 첫 불일치에서 FAIL로 중단한다. 로그에는 벡터·사이클·시점·신호·실제값·기대값을 남기며 Weight는 bank 인덱스를 식별한다.
- 마지막 읽기 응답까지 비교하고, 출력별 예정 비교 수·전체 벡터 수·종료 시점이 모두 맞을 때만 PASS를 출력한다. Timeout이나 검사 완료 전 종료는 FAIL이다.

`90_scripts/sim_targets.json`의 `memory_wrapper` 타깃에 형식 버전·출력 수 7·예상 parameter와 `verification_scope=memory_wrapper_standalone`을 등록했다. 소스 목록은 실제 Memory 계층 6개 파일과 TB·tester를 명시하며 임시 모델을 포함하지 않는다. 공통 실행기는 기존 생성 데이터를 사용하고 생성기를 자동 호출하지 않는다.

후속 실행 명령은 다음과 같다. `tb_memory_wrapper` 이름으로도 같은 타깃을 선택할 수 있다.

```powershell
python project/90_scripts/run.py memory_wrapper
```

초기 미구현 Memory를 연결한 TB·tester의 컴파일·계층 전개는 통과했다. Xsim은 벡터 0의 첫 비교(40 ns)에서 `in_data`가 기대값 0 대신 X여서 FAIL로 중단했다. 기록은 `07_runs/memory_wrapper_xsim_20261109_102809_776349Z/`에 남아 있다. 이는 당시 비어 있던 하위 RTL의 불일치를 검출한 결과이며 Memory 기능 검증 PASS가 아니다. 파형은 기록하지 않았다.

### 5.10. 하위 RTL 구현·단독 검증 결과

사용자 요청에 따라 실제 Memory 하위 모듈 5개의 동작을 작성했다. 구현 내용은 [Memory 모듈 명세 14절](../modules/memory_wrapper.md#14-구현검증-상태)에 기록한다. 기존 golden·헤더·TB·tester·비교 마스크는 변경하지 않았다.

사용자 요청에 따라 실제 Memory RTL을 연결한 단독 검증을 실행했다. 컴파일·계층 전개·xsim을 통과했으며 공통 실행기는 종료 코드 0, PASS로 판정했다.

| 항목 | 실제 결과 |
| --- | --- |
| 검증 범위 | `memory_wrapper_standalone`, 임시 모델 없음 |
| 데이터 | 기존 MNIST test sample 0 Memory golden |
| 벡터 | 265,015 / 265,015 완료 |
| 출력 비교 | 1,708,021회 |
| 명세상 마스크 제외 | 147,084회 |
| 오류 | 0 |

기록은 `07_runs/memory_wrapper_xsim_20261109_103936_500210Z/`의 `manifest.json`, `metrics.json`, `README.md`와 로컬 상세 로그·소스 사본에 보존했다. 위 초기 미구현 버전의 FAIL 기록은 그대로 유지한다. 이번 PASS는 확정한 정상 흐름의 실제 Memory 단독 검증에 한정하며, 실제 Control RTL과 연결한 Top 검증이나 합성·BRAM 매핑·타이밍 검증을 뜻하지 않는다. 별도 테스트 스위트는 실행하지 않았고 파형은 기록하지 않았다.

별도 후속 실행에서는 실제 Top·Control·Memory에 MAC·누산기 모델을 연결해 Top 검증을 통과했다. 기록은 `07_runs/mlp_top_xsim_20261109_104742_239167Z/`이며 265,015개 벡터·913,467회 비교·오류 0·prediction 7이다. 상세 범위는 [Top 검증 명세 11절](mlp_top.md#11-실제-memory로-교체한-후속-검증-구성)을 따른다. MAC·누산기는 모델이므로 전체 실제 RTL 검증 완료로 간주하지 않는다.

## 6. 수치·메모리 기준

메모리 검증에서는 초기화한 주소와 아직 쓰지 않은 주소를 구분한다. 초기화하지 않은 BRAM을 임의로 0이라고 가정하지 않는다. 읽기 지연, 쓰기 시점, TB/추론 접근 선택, A/B 역할 전환과 이전 데이터 유지도 검증한다.

### 공통 실행 환경

- **사용자 확정: 시뮬레이터는 xsim을 사용한다.**
- 기본 검증 결과는 tester의 자동 비교와 텍스트 로그로 확인한다.
- **사용자 확정: 파형 확인은 사용자가 별도로 요청한 경우에만 수행한다.** 파형 수동 확인을 기본 검증 절차나 PASS 판정의 필수 조건으로 두지 않는다.
- **사용자 확정: 기본 실행에서는 파형을 기록하지 않는다.** 파형 기록·확인은 사용자가 별도로 요청한 경우에만 설정한다.
- **사용자 확정: 데이터 생성기와 xsim은 분리해서 각각 수동 실행한다.** 생성기를 먼저 실행해 사용할 입력·기대값·데이터 헤더를 모두 준비하고, 이후 별도의 시뮬레이션 실행 스크립트를 실행한다.
- 시뮬레이션 실행 스크립트는 미리 생성한 데이터를 사용하며, 데이터 생성기를 자동 호출하거나 데이터를 자동 재생성하지 않는다.
- 생성 데이터의 설정 불일치는 기존 규칙대로 오류로 처리한다. 데이터가 누락된 경우에도 자동 생성하지 않고 준비 오류로 알린다.
- **사용자 확정: 시뮬레이션 실행 스크립트는 Python으로 작성하며, 한 번의 실행에서는 한 모듈만 검증한다.** 사용자가 검증할 모듈을 직접 골라 실행한다.
- 모듈별 Python 실행 스크립트를 따로 두거나, 공통 Python 실행 스크립트에서 한 모듈을 명시적으로 선택하는 구성을 사용할 수 있다. 구체적인 파일명·위치·명령은 구현 시 정한다.
- **사용자 확정: 전체 통합 검증은 Top 모듈의 TB·tester로 수행한다.** 모든 모듈 테스트를 한꺼번에 순회하는 실행 방식은 사용하지 않는다.

**사용자 확정: Timeout은 Python에서 계산한 예상 실행 사이클 수에 100클럭의 여유를 더한 값으로 한다.**

- 정의된 출력은 비트 단위로 비교한다. `!==` 비교로 예상하지 않은 X/Z도 불일치로 검출한다.
- 선언 폭·parameter와 생성 데이터의 설정이 다르면 검사를 진행하지 않고 오류로 처리한다.
- Timeout, 불일치, 벡터 누락 또는 실제 비교 없이 종료한 경우 PASS로 처리하지 않는다.
- 오류가 없고 예정된 검사를 모두 완료했을 때 PASS로 판정한다.
- 불일치 로그에는 모듈명, 벡터 번호·시점, 신호명, 실제값과 기대값을 남긴다. 배열 출력은 lane도 식별한다.
- **사용자 확정: 기본 로그는 불일치 상세와 최종 요약으로 한다.** 최종 요약에는 검사 수·오류 수와 PASS/FAIL을 남긴다. 정상 일치한 벡터의 값을 매번 출력하지 않는다.
- 생성 설정과 데이터 출처, 실행 도구·결과를 재현할 수 있게 기록한다. 실제 파일 위치와 실행 명령은 구현 시 정한다.

### 불일치 처리와 개별 모듈 실행

- **사용자 확정: 첫 불일치에서 해당 모듈의 실행을 중단한다.** 모듈명, 벡터 번호·시점, 신호명, 실제값·기대값을 기록하고 FAIL로 남긴다. 배열 출력은 lane도 식별한다.
- **사용자 확정: 실패 확인 후 어떤 모듈을 실행할지는 사용자가 직접 판단한다.** 실행 스크립트는 실패한 모듈에서 다른 모듈로 자동 이동하지 않는다.
- 검증하고 싶은 모듈만 직접 실행하고, 건너뛸 모듈은 실행하지 않는 방식으로 모듈 단위 선택·제외를 수행한다. 개별 테스트 케이스 선택·제외와 전체 모듈 일괄 실행은 현재 지원 범위에 포함하지 않는다.
- 다른 모듈을 실행하더라도 기존 실패 기록은 FAIL로 유지한다. 실행하지 않은 모듈을 검증 완료나 PASS로 처리하지 않는다.
- 기대값 변경이나 비교 마스크 확대로 불일치를 숨기지 않는다. 선택한 모듈에서는 정의된 출력을 계속 비교한다.

컴파일·계층 전개 통과와 기능 검증 PASS를 구분한다. 단독 golden·데이터 헤더·TB·tester를 준비했고, 초기 미구현 Memory의 xsim에서 첫 불일치를 검출했다. 이후 하위 RTL을 구현하고 기존 golden으로 실제 Memory 단독 xsim 검증을 통과했다. 기존 Python 정확도·golden 생성 성공이나 임시 모델을 연결한 Top PASS와 실제 Memory 단독 RTL PASS는 구분하며, 전체 실제 RTL 통합 검증 완료로 확대하지 않는다.

## 8. 남은 구체화

- 하위 모듈 개별 TB의 구체적인 범위와 parameter 조합, 정상 흐름 외의 추가 사례.
- 미사용·범위 밖·비정렬 주소 및 정상 흐름 밖 동시 요청의 동작은 정의하지 않으며 최초 시나리오에서 제외한다.
- 생성기의 별도 테스트, 전체 실제 RTL 통합 검증 및 합성·BRAM 매핑·타이밍 확인은 별도 요청에 따라 단계별로 진행한다.

공통 실행기는 `90_scripts/run.py`이며, `90_scripts/sim_targets.json`에 `memory_wrapper` 타깃이 등록되어 있다. 단독 TB·tester·데이터 헤더와 실행 설정을 준비해 현재 구현한 Memory RTL의 정상 흐름 PASS를 확인했다. 생성기와 xsim의 수동 분리 실행 원칙은 유지한다.

미정 동작은 기대값을 임의로 확정해 생성하지 않는다. 해당 사항을 정한 뒤 생성기와 tester에 함께 반영한다.
