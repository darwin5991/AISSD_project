# MAC array 검증 명세서

출처: [RTL 검증 계획](../verification.md). 공통 규칙과 해당 모듈의 검증 항목을 원문에서 옮겼다. 이후 사용자가 확정한 사항을 반영하며, 나머지 미정 사항은 확정하지 않는다.

## 1. 검증 방식

이 문서는 공통 검증 환경과 사용자가 확정한 MAC array 단독 검증 범위·비교 규칙을 함께 기록한다. 명세의 확정과 코드 작성·실행 승인은 구분한다.

- 모듈별로 TB, tester, 데이터 헤더를 한 세트로 구성한다.
- Python에서 테스트 입력과 기대 출력을 미리 계산하고 파일로 생성한다.
- Tester는 생성된 입력을 공급하고 기대값과 비교한다. RTL과 같은 연산을 다시 구현해 정답을 계산하지 않는다.
- 데이터 출력뿐 아니라 valid, 주소, enable, busy, done 등 해당 모듈의 모든 출력 포트를 검증 대상으로 둔다.
- 순차 출력과 조합 출력을 구분해 값과 변화 시점을 확인한다.
- 시점 판단은 명세를 따른다. 기준 모델은 명세에서 작성하고, DUT의 실제 출력을 기대값으로 사용하지 않는다.

참고한 deit_fpga의 단위 TB는 TB와 tester를 분리하고, tester에서 자동 생성된 `<module>_tb_data.vh`를 include한다. 참고 프로젝트의 Top TB는 tester 역할을 TB 내부에 포함하지만, AISSD에서는 Top도 TB와 tester를 분리하는 구성을 따른다.

사용자가 지정한 `deit_fpga/tb/`에서 다음 소스를 읽고 구조를 확인했다. 참고 프로젝트의 시뮬레이션은 실행하지 않았다.

- `tb_mac_array/tb_mac_array.v`, `mac_array_tester.v`, `mac_array_tb_data.vh`: TB의 클럭·reset·DUT/tester 연결·timeout, tester의 데이터 헤더 include·parameter 일치 검사·하강 에지 비교 후 입력 공급·오류 집계·PASS/FAIL 출력을 확인했다.
- `tb_sm_rowsum_acc/tb_sm_rowsum_acc.v`, `sm_rowsum_acc_tester.v`: TB와 tester 분리, valid와 데이터를 함께 비교하는 구성을 확인했다. 이 tester의 `#2` 중간 시점 추가 검사는 AISSD에 적용하지 않으며, 확정한 하강 에지 비교 방식을 따른다.
- `tb_vt_top/tb_vt_top.v`: Top TB 내부에 입력 공급·비교 역할이 함께 있는 구성을 확인했다. AISSD의 Top은 기존 확정대로 TB와 tester를 분리한다.

참고 소스의 reset 극성·유지 길이·데이터와 모듈 구조는 그대로 옮기지 않는다. AISSD에서 확정한 reset·수치 형식·실제 MNIST 데이터·모듈 구성을 따른다.

## 2. 파일 역할과 구성

| 파일 | 담당 역할 |
| --- | --- |
| `tb_<module>.sv` | 클럭·리셋, DUT·tester 인스턴스와 신호 연결, 전체 timeout |
| `<module>_tester.sv` | 입력 공급, 출력 비교, 검사·오류 수 집계, 불일치 로그와 PASS/FAIL |
| `<module>_tb_data.vh` | 입력·기대 출력·비교 마스크 배열, 벡터 수와 실제 생성 설정 |
| `<module>_golden.py` | 입력 생성, 독립 기준 계산, 클럭별 상태 추적과 데이터 헤더 출력 |

모듈별 TB·tester·데이터 헤더 세 파일을 같은 TB 폴더에 둔다.

**사용자 확정: `05_tb/`의 분류는 `04_rtl/`의 구성을 따른다.** `common/`, `mac_array/`, `accumulator_postprocess/`, `memory/`, `controller/`로 구분한다. Top과 Control unit은 해당 RTL과 같이 `controller/`에 둔다.

**사용자 확정: Python golden 생성기는 `03_model/golden/`에 모아 두고, 실제 사용하는 `.vh` 파일은 해당 TB·tester와 함께 둔다.**

```text
project/05_tb/mac_array/
├── tb_mac_array.sv
├── mac_array_tester.sv
└── mac_array_tb_data.vh

project/03_model/golden/mac_array_golden.py
```

데이터 헤더에는 자동 생성 파일임을 표시하며 Python을 통해 갱신한다. 수동으로 기대값을 고쳐 RTL에 맞추지 않는다. 생성기 파일명은 위 패턴을 기준으로 하고, 공통 출력 형식과 보조 함수는 재사용할 수 있다.

## 3. Python이 생성할 데이터

| 데이터 | 내용 |
| --- | --- |
| 입력 벡터 | 각 단계에서 tester가 DUT에 공급할 데이터·설정·제어 값 |
| 기대 출력 | 명세와 동일한 정수 연산 및 상태 전이로 계산한 모든 출력 |
| 비교 시점 | 각 하강 에지의 입력 변경 전 비교 시점과 출력별 클럭 지연을 명시 |
| 비교 마스크 | 명세상 값이 정의되지 않은 출력·비트에 한해 비교 제외 범위 명시 |
| 생성 정보 | 벡터 수, 폭·parameter, 소수 비트·shift, 사용한 seed 등 재현 정보 |

Signed 값은 폭에 맞는 2의 보수 비트 패턴으로 저장한다. 배열 포트의 lane 순서와 32비트 워드의 첫 바이트 [7:0] 배치를 명시한다.

**사용자 확정: 최초 Top 검증은 MNIST test 이미지 0번(sample ID = 0) 한 장으로 수행하며, 대부분의 시뮬레이션 시나리오는 해당 이미지의 실제 추론 데이터를 사용한다.** 중간 모듈 검증도 같은 추론 과정에서 발생하는 실제 연산 입력과 중간 결과를 사용하며, 무작위 데이터를 기본 검증 입력으로 사용하지 않는다.

**사용자 확정: 최초 시나리오는 이미지 0번의 정상 추론 1회 흐름을 사용한다.** MAC 단독 검증은 FC1~FC3의 실제 입력·가중치와 부분합·valid 전달을 확인한다. MAC에는 `start`·`busy`·`done` 포트가 없으므로 해당 신호 자체를 검증하지 않는다. 실행 중 추가 start와 재실행 등 예외 시나리오는 최초 검증에 포함하지 않는다.

실제 데이터는 Python 기준 모델에서 생성한다. RTL의 출력을 기대값으로 사용하지 않는다. 동일 이미지의 입력·weight·bias·부분합·누산값·레이어별 출력을 모듈별 검증에 활용하고, 제어 신호의 기대값은 명세의 실행 일정에 따라 독립적으로 계산한다.

**사용자 확정: 무작위 데이터가 필요한 경우 seed는 42를 사용하고 기록한다.** 최초 MAC 검증은 FC1~FC3 전체의 실제 추론 데이터를 사용하며, 별도의 부호 경계값·임의 valid 공백·무작위 사례를 추가하지 않는다. 전체 벡터 수는 실제 공급 일정의 공백과 파이프라인 마무리를 포함해 계산한다.

같은 이미지의 실제 레이어 입력·weight를 MAC 입력으로 사용하고, 해당 연산의 부분합을 기대값으로 사용한다.

`valid=0`이라는 이유만으로 데이터 출력을 모두 비교에서 제외하지 않는다. 명세상 값이 정해지는 출력은 계속 비교한다. 비교 마스크는 미구현 동작이나 불일치를 숨기는 용도로 사용하지 않는다.

## 4. 입력 공급과 비교 시점

**사용자 확정: TB 클럭 주기는 10 ns(100 MHz)로 한다.**

**사용자 확정: 시뮬레이션 시간 단위는 1 ns, 시간 정밀도는 1 ps로 한다.**

클럭·리셋은 TB에서 발생시키며, Python 기준 모델도 같은 reset 조건과 초기 상태를 사용한다.

**사용자 확정: Reset은 비동기 active-low이며, 시뮬레이션 시작 시 3주기(30 ns) 동안 유지한 뒤 클럭 하강 에지에서 해제한다.**

**사용자 확정: 레지스터 출력과 조합 출력을 포함한 모든 출력은 클럭 하강 에지에서 기대값과 비교한다.** 출력 비교를 위해 별도 1 ns 지연을 두지 않는다.

입력 공급과 비교는 다음 순서로 진행한다.

1. 클럭 하강 에지에서 현재까지 유지한 입력과 내부 상태에 대한 모든 출력을 기대값과 비교한다.
2. 비교를 마친 뒤 다음 벡터의 입력·설정·제어 값을 공급한다. 해당 값은 다음 하강 에지의 비교를 마칠 때까지 유지한다.
3. 다음 상승 에지에서 DUT가 입력을 처리한다.
4. 다음 하강 에지에서 출력별로 명세에 정해진 클럭 지연을 반영한 기대값과 비교하고, 같은 순서로 반복한다.
5. 마지막 입력 뒤에도 필요한 파이프라인 지연만큼 검사를 이어가 마지막 결과까지 비교한다.

같은 하강 에지에서 새 입력 공급과 출력 비교를 수행할 때는 반드시 비교를 먼저 한다. 새 입력에 대한 조합 출력을 입력 변경과 동시에 비교하지 않는다. 별도의 클럭이 없는 조합 하위 모듈도 TB 클럭의 하강 에지를 비교 기준으로 사용한다.

**사용자 설계 방향: 큰 모듈은 내부 중간 레지스터가 있는 순차 경로를 사용한다.** 중간 레지스터 뒤의 조합 후처리는 허용하며, 출력단이 조합회로라는 이유만으로 추가 출력 레지스터를 요구하지 않는다.

출력별 순차·조합 여부와 클럭 지연은 각 모듈 명세를 따른다. Python 기준 모델도 같은 하강 에지에서 비교할 값을 생성한다.

## 5. 모듈별 검증 항목

아래는 의존 관계에 따른 권장 순서다. 실제 구현 시작 모듈과 세부 사례는 해당 작업을 시작할 때 정한다.

| 단계 | 대상 | 주요 검증 항목 |
| --- | --- | --- |
| 3 | dot_product4, MAC array | 균형 트리 계산, 두 레지스터 단계, 공통 valid와 공백 전달 |

하위 모듈도 각자의 입력·출력을 직접 검증한다. 상위 검증에서는 같은 하위 모듈이 연결된 결과와 전체 시점 관계를 확인한다.

### 5.1. 확정한 데이터 범위

**사용자 확정: 이미지 0번의 FC1~FC3 전체를 검증하며, 유효 입력은 총 29,280묶음이다.** 각 묶음은 공통 입력 signed 8비트 4개와 가중치 signed 8비트 4×4개다. 출력은 signed 32비트 부분합 4개와 공통 `psum_valid`다. Bias 초기화·누산·후처리는 MAC 검증 범위에 포함하지 않는다.

| 레이어 | 출력 묶음 수 | 묶음당 입력 워드 수 | 유효 MAC 입력 수 |
| --- | ---: | ---: | ---: |
| FC1 | 128 | 196 | 25,088 |
| FC2 | 32 | 128 | 4,096 |
| FC3 | 3 | 32 | 96 |
| 합계 | — | — | 29,280 |

29,280은 `input_valid=1`인 입력 묶음 수이며 전체 TB 벡터 수가 아니다. FC3 더미 출력 2개도 lane별 부분합 비교에 포함한다. 각 lane g는 `weight_data[g][k]`와 공통 `input_data[k]`의 네 곱을 계산하며, 가중치의 첫 번째 배열 축은 출력 lane, 두 번째 축은 입력 위치다.

### 5.2. 공백 구간의 입력·가중치

**사용자 확정: `input_valid=0`인 공백에도 실제 Top의 Memory 출력 흐름을 Python에서 재현해 공급한다.** 공백이라는 이유로 입력·가중치를 일괄 0으로 바꾸지 않는다.

- 메모리 읽기 출력 유지, 읽기에 따른 갱신 및 A/B 버퍼 선택 변경을 명세에 따라 반영한다.
- DUT의 실제 출력이나 내부 상태에서 입력·기대값을 가져오지 않는다. Python 기준 모델이 실제 데이터와 명세 일정으로 흐름을 구성한다.
- `input_valid=0`이어도 MAC 데이터 레지스터는 매 클럭 갱신된다. 따라서 그때 공급한 입력·가중치로 계산되는 부분합도 기대값에 포함한다.
- 정상 흐름에 포함된 묶음 사이 공백·레이어 전환을 사용한다. 별도의 임의 valid 공백이나 경계 사례는 최초 시나리오에 추가하지 않는다.

### 5.3. 부분합·valid 비교 규칙

**사용자 확정: 부분합 4개와 `psum_valid`를 같은 파이프라인 시점에 비교한다.** 데이터와 valid는 모두 곱셈 결과 레지스터·부분합 레지스터에 대응하는 2단 경로를 따른다.

| 출력 | 기대값 | 비교 범위 |
| --- | --- | --- |
| `partial_sum[0:3]` | lane별 `(p0+p1)+(p2+p3)`. 각 곱은 signed 8비트 곱셈 후 signed 32비트 부호 확장, 두 덧셈 레벨도 signed 32비트 | 각 lane을 비교하며 `psum_valid=0`인 구간도 포함 |
| `psum_valid` | 동일 입력의 `input_valid`를 2단 레지스터로 전달한 값 | 정상 전달·공백·파이프라인 마무리 모두 비교 |

입력 공급과 비교의 벡터 관계는 다음과 같다. M은 벡터 i의 입력을 샘플링하는 상승 에지다.

| 시점 | 동작 |
| --- | --- |
| 하강 에지 벡터 i | 현재 출력을 먼저 비교한 뒤 입력·가중치·`input_valid` 공급 |
| 상승 에지 M | 해당 입력의 곱셈 결과와 valid 1단 갱신 |
| 하강 에지 벡터 i+1 | 해당 입력의 부분합이 나오기 전, 이전 파이프라인 결과 비교 |
| 상승 에지 M+1 | 해당 입력의 부분합 4개와 `psum_valid` 갱신 |
| 하강 에지 벡터 i+2 | 벡터 i에서 공급한 입력의 부분합 4개와 valid 비교 |

Reset은 명세대로 곱셈 결과·부분합·valid 파이프라인 레지스터를 모두 비동기로 0 초기화한다. Reset 해제 후 파이프라인이 채워지는 구간도 이 초기 상태와 실제 공급 입력을 기준으로 기대값을 만든다.

`input_valid=0` 또는 `psum_valid=0`이라는 이유로 정의된 부분합을 마스크로 제외하지 않는다. 마지막 검증 대상 입력의 결과까지 비교하도록 필요한 마무리 벡터를 포함한다. 확정한 재현 구간·타이밍·헤더 형식은 5.4~5.6절을 따른다.

### 5.4. 전체 재현 구간과 벡터 타이밍

**사용자 확정: 추론 구간만 잘라 사용하지 않고 Top의 초기화부터 최종 읽기까지 전체 흐름을 재현한다.** Top과 동일한 클럭·reset·단계 일정으로 MAC에 보이는 입력·가중치·valid를 Python에서 만든다. Memory·Control RTL을 실행하거나 DUT 내부를 관측해 벡터를 가져오는 방식은 사용하지 않는다.

| Top의 단계 | MAC에 재현할 입력 흐름 |
| --- | --- |
| 전체 메모리 초기화 쓰기 | Reset으로 0이 된 Memory 읽기 출력에 따라 입력·가중치 0, `input_valid=0` 공급 |
| 초기화 확인용 전체 읽기 | TB 읽기로 갱신되는 Memory 읽기 출력과 버퍼 선택을 반영. `input_valid=0`이어도 실제 데이터 변화와 부분합 계산을 재현 |
| FC1~FC3 | 실제 레이어 입력·가중치와 명세의 `input_valid` 일정 공급. 묶음 사이 공백·레이어 준비·버퍼 전환 포함 |
| ARGMAX·완료 | MAC valid가 비활성인 동안에도 Memory 읽기·버퍼 선택에 따른 데이터 흐름을 반영 |
| 최종 A/B 전체 읽기 | 외부 TB 읽기에 따라 MAC에 보이는 데이터의 갱신·유지를 반영 |
| 파이프라인 마무리 | 마지막 Top 시점에 공급한 입력의 부분합·valid를 2단 지연 뒤까지 비교 |

초기화 쓰기 구간에도 MAC은 매 클럭 계산한다. 유효 입력이 없다는 이유로 파이프라인을 멈추지 않는다. 초기화 확인용 읽기 이후에는 `input_valid=0`인 구간의 부분합도 0이라고 가정하지 않는다.

**사용자 확정: 첫 비교·입력 공급은 40 ns 하강 에지이며, 마지막 대상 입력 뒤 2단 지연을 모두 비교한 뒤 종료한다.** 클럭 초기값은 기존 Top처럼 0, reset 해제는 30 ns 하강 에지다. 입력·가중치·valid의 초기 공급값은 0이며, 벡터 0에서 reset 이후 초기 출력을 비교한 뒤 해당 시점의 Top 입력 흐름을 공급한다. 첫 입력은 45 ns 상승 에지에서 곱셈 결과 레지스터에 반영된다.

Top의 재현 시점이 T개이면 벡터 0~T-1에서 해당 입력들을 공급한다. 마지막 입력 T-1의 결과는 벡터 T+1에서 비교하므로 전체 비교 벡터 수는 T+2개다. 마지막 비교 뒤에 별도 대기를 추가하지 않는다.

아래 값은 기존 Top 일정과 위 2단 마무리 규칙에서 계산한 명세상 값이며, MAC 생성기나 RTL을 실행한 결과가 아니다.

| 항목 | 명세상 계산값 |
| --- | ---: |
| 기존 Top 재현 시점 수 T | 265,015 |
| MAC 비교 벡터 수 T+2 | 265,017 |
| 첫 벡터 시점 | 40 ns |
| Reset·대기·마지막 검사까지 예상 TB 사이클 | 265,020 |
| 예상 마지막 비교 시점 | 2,650,200 ns |
| Timeout = 예상 + 100클럭 | 265,120주기 |

### 5.5. 데이터 헤더와 비교 마스크 형식

**사용자 확정: 입력·기대값·마스크는 신호·lane별 배열로 구성한다.** 각 배열의 인덱스는 동일한 하강 에지 벡터를 뜻한다. 기존 Control·Memory와 같이 기대값을 먼저 비교하고 같은 인덱스의 입력을 새로 공급한다.

- 입력은 `input_valid`와 signed 8비트 `input_data` 4개·`weight_data` 4×4개를 구분한다. Weight의 순서는 `[출력 lane][입력 위치]`다. `clk`·`rst_n`은 TB가 공급한다.
- 기대 출력은 signed 32비트 `partial_sum` 4개와 1비트 `psum_valid`를 각각 구분한다. 총 5개 출력값을 비교한다.
- **사용자 확정: 비교 마스크는 출력별·벡터별 1비트다.** 부분합은 lane별로 두고, 1이면 해당 32비트 전체를 비교한다. `psum_valid`에도 독립적인 1비트 마스크를 둔다.
- 이번 정상 시나리오에서는 공급 입력과 reset 초기 상태가 정의되므로 부분합·valid를 모두 계속 비교한다. 유효 표시가 0인 구간도 마스크로 제외하지 않는다.
- Signed 값은 선언 폭에 맞는 2의 보수 비트 패턴으로 저장한다. 첫 데이터가 워드 `[7:0]`에 있는 기존 메모리 배치와 MAC 배열 순서를 연결해 기록한다.
- 헤더에는 형식 버전·sample ID·벡터 수·시간 설정·단계 경계·예상 실행 사이클·timeout 및 원본·생성 실행 식별 정보를 남긴다.

### 5.6. 원본 지정과 생성 결과 보존

### 5.7. 생성기 코드와 데이터 생성 결과

단독 생성기 소스는 [mac_array_golden.py](../../03_model/golden/mac_array_golden.py)에 작성했다. 기존 Python 메모리 기준 모델·Top 원본 로더·Control 일정을 재사용하며, 해당 생성기들의 `generate()`나 RTL·시뮬레이터를 자동 실행하지 않는다.

- 입력·가중치는 각 시점의 기존 BRAM 읽기 출력과 현재 Top 버퍼 선택으로 구성한다. 다음 상승 에지의 메모리 읽기 결과를 미리 공급하지 않는다.
- 기존 Memory 단독 벡터에서 미사용 `buf_sel`에 둔 0은 그대로 MAC 데이터 선택에 사용하지 않는다. 현재 Control LUT가 정상 흐름에서 유지하는 레이어·ARGMAX 버퍼 선택을 반영한다. ARGMAX 준비 이후 새 start/reset 없이 최종 읽기까지 B 선택을 유지하는 기존 동작도 포함한다.
- 입력은 `input_valid`, `input_data_lane0`~`input_data_lane3` 및 `weight_data_lane<g>_input<k>`로 구분한다. 기대 출력은 `partial_sum_lane0`~`partial_sum_lane3`, `psum_valid`이며, 각 출력마다 벡터별 1비트 마스크를 둔다.
- 원본 부분합 NPZ의 signed int32 형식·배열 순서와 HEX 해시·2의 보수 배치를 확인하도록 작성했다. 유효 연산은 저장된 입력·가중치·부분합과 대조하고, 공백도 signed 곱셈과 두 덧셈 단계로 계산한다.
- 부분합·valid를 2단 지연해 기대값을 구성하고 5개 출력을 모든 벡터에서 비교할 데이터를 준비한다. 마지막 두 마무리 구간에는 새 valid를 넣지 않고 입력·가중치를 유지한다.
- 헤더·NPZ·실행 기록·소스 사본을 보존하고 NPZ 재읽기와 해시 확인 뒤 고정 TB 헤더를 갱신하도록 작성했다. 원본 오류나 생성 실패로 기존 TB 헤더를 먼저 덮어쓰지 않는다.

사용자 요청에 따라 `aissd` 환경에서 기존 이미지 0번 원본을 지정해 생성기를 실행했다. 종료 코드 0으로 원본 해시·배치, 메모리 흐름, MAC 부분합·valid 지연, 저장된 레이어별 부분합 대조 및 NPZ 재읽기 검사를 통과했다. 별도 테스트 스위트나 RTL 기능 검증 결과는 아니다.

- 생성 결과: `07_runs/mac_array_golden_20261109_140711_041499Z/`.
- 고정 TB 헤더: `05_tb/mac_array/mac_array_tb_data.vh`.
- 전체 벡터 265,017개: Top 재현 265,015개와 마무리 2개.
- 유효 입력·출력 각각 29,280묶음, 예상 실행 265,020주기, timeout 265,120주기.

- 고정 헤더·보존 헤더·벡터 NPZ의 SHA-256을 실행 manifest와 대조해 일치를 확인했다.

### 5.8. 작성한 TB·tester와 실행 타깃

[tb_mac_array.sv](../../05_tb/mac_array/tb_mac_array.sv)는 10 ns 클럭·3주기 reset, 실제 MAC DUT와 tester의 배열 포트 연결 및 전체 timeout을 담당한다. 단독 TB에 Control·Memory RTL이나 MAC 임시 모델을 연결하지 않는다.

[mac_array_tester.sv](../../05_tb/mac_array/mac_array_tester.sv)는 기존 생성 헤더를 include하고 다음 동작을 수행하도록 작성했다.

- 헤더 형식·sample ID·벡터 길이·단계 경계·2단 지연·시간 설정·포트 폭·lane 차원과 입력·기대값의 X/Z를 확인한다.
- 부분합 4개·`psum_valid`의 마스크가 모든 벡터에서 1인지 확인한다. `psum_valid=0`인 부분합도 비교하며 tester 내부에서 곱셈·덧셈 기대값을 다시 계산하지 않는다.
- 각 하강 에지에서 모든 출력 비교를 마친 뒤 `input_valid`, 입력 4개·가중치 16개를 공급한다.
- `!==`로 데이터·valid와 예상하지 않은 X/Z를 비교하고 첫 불일치에서 FAIL로 중단한다. 로그에 벡터·사이클·시점·신호·lane·비트 패턴과 signed 실제값·기대값을 남긴다.
- 마지막 입력의 2단 지연 응답까지 확인하고, 출력별 비교 수·전체 벡터 수·유효 입력/출력 수·종료 시점이 모두 맞을 때만 PASS로 판정한다. Timeout이나 검사 완료 전 종료는 FAIL이다.

`90_scripts/sim_targets.json`의 `mac_array` 타깃에는 `MAC_DATA_FORMAT_VERSION`, 출력 수 5, 예상 parameter와 `verification_scope=mac_array_standalone`을 등록했다. 컴파일 소스는 실제 MAC 계층 4개와 공통 `register_en`·`delay_line`·`signed_adder32`, TB·tester를 명시하며 임시 모델을 포함하지 않는다.

후속 실행 명령은 다음과 같다. `tb_mac_array` 이름으로도 같은 타깃을 선택할 수 있다. 공통 실행기는 기존 생성 데이터를 사용하며 생성기를 자동 호출하지 않는다.

```powershell
python project/90_scripts/run.py mac_array
```

하위 연산기 구현 전 `07_runs/mac_array_xsim_20261109_142627_223407Z/`에서 컴파일·계층 전개는 통과했다. xsim은 40 ns의 벡터 0에서 `partial_sum[0]`이 기대값 0 대신 X여서 첫 비교 후 FAIL로 중단했다. 이 실행의 `rtl_verified`는 `false`다. 생성 헤더가 Vivado의 줄 번호 표시 한도를 넘는다는 컴파일 경고도 기록되었다.

이후 `signed_multiplier8`에 signed 8비트 곱의 16비트 결과를 32비트로 부호 확장하는 조합회로를, 공통 `signed_adder32`에 signed 32비트 조합 덧셈을 작성했다. 기존 레지스터·2단 valid 지연·배선은 유지했다. 생성 헤더·기대값·비교 마스크는 수정하거나 재생성하지 않았다. 파형은 기본 실행에서 기록하지 않는다.

연산기 구현 후 `07_runs/mac_array_xsim_20261109_143252_014262Z/`에서 컴파일·계층 전개·xsim을 통과했다. 실제 MAC RTL만 사용하는 단독 검증이며 임시 모델은 없다.

- 전체 265,017개 벡터, 출력 비교 1,325,085회, 마스크 제외 0회, 오류 0개.
- `psum_valid=0`인 부분합과 마지막 입력의 2단 지연까지 비교하고 2,650,200 ns에 정상 종료했다.
- 실행 결과는 `PASS`, `rtl_verified=true`, 범위는 `mac_array_standalone`이다.
- MAC 단독 실행의 헤더 줄 번호 한도 경고는 남아 있다. 이후 실제 MAC을 연결한 Top 검증과 실행기 테스트 12개도 통과했다. 합성·타이밍 및 전체 실제 RTL 통합 검증은 수행하지 않았다.

## 6. 수치·메모리 기준

- 입력·weight·bias·레이어 출력은 signed 8비트다.
- 곱셈·adder tree·부분합·누산·결과 레지스터는 signed 32비트다.

기존 [generate_golden.py](../../03_model/generate_golden.py)는 이미지 한 장의 BRAM 초기화 데이터, 레이어별 출력·부분합·누산 정답을 생성한다. 이 데이터는 연산 정답이며 클럭별 출력 벡터 자체는 아니다. 모듈별 생성기에서 재사용할 때 입력 공급 순서와 지연을 반영해 `.vh`로 변환한다.

### 공통 실행 환경

- **사용자 확정: 시뮬레이터는 xsim을 사용한다.**
- 기본 검증 결과는 tester의 자동 비교와 텍스트 로그로 확인한다.
- **사용자 확정: 파형 확인은 사용자가 별도로 요청한 경우에만 수행한다.** 파형 수동 확인을 기본 검증 절차나 PASS 판정의 필수 조건으로 두지 않는다.
- **사용자 확정: 기본 실행에서는 파형을 기록하지 않는다.** 파형 기록·확인은 사용자가 별도로 요청한 경우에만 설정한다.
- **사용자 확정: 데이터 생성기와 xsim은 분리해서 각각 수동 실행한다.** 생성기를 먼저 실행해 사용할 입력·기대값·데이터 헤더를 모두 준비하고, 이후 별도의 시뮬레이션 실행 스크립트를 실행한다.
- 시뮬레이션 실행 스크립트는 미리 생성한 데이터를 사용하며, 데이터 생성기를 자동 호출하거나 데이터를 자동 재생성하지 않는다.
- 생성 데이터의 설정 불일치는 기존 규칙대로 오류로 처리한다. 데이터가 누락된 경우에도 자동 생성하지 않고 준비 오류로 알린다.
- **사용자 확정: 시뮬레이션 실행 스크립트는 Python으로 작성하며, 한 번의 실행에서는 한 모듈만 검증한다.** 사용자가 검증할 모듈을 직접 골라 실행한다.
- 모듈별 Python 실행 스크립트를 따로 두거나, 공통 Python 실행 스크립트에서 한 모듈을 명시적으로 선택하는 구성을 사용할 수 있다. 구체적인 파일명·위치·명령은 구현 시 정한다.
- **사용자 확정: 전체 통합 검증은 Top 모듈의 TB·tester로 수행한다.** 모든 모듈 테스트를 한꺼번에 순회하는 실행 방식은 사용하지 않는다.

**사용자 확정: Timeout은 Python에서 계산한 예상 실행 사이클 수에 100클럭의 여유를 더한 값으로 한다.**

- 정의된 출력은 비트 단위로 비교한다. `!==` 비교로 예상하지 않은 X/Z도 불일치로 검출한다.
- 선언 폭·parameter와 생성 데이터의 설정이 다르면 검사를 진행하지 않고 오류로 처리한다.
- Timeout, 불일치, 벡터 누락 또는 실제 비교 없이 종료한 경우 PASS로 처리하지 않는다.
- 오류가 없고 예정된 검사를 모두 완료했을 때 PASS로 판정한다.
- 불일치 로그에는 모듈명, 벡터 번호·시점, 신호명, 실제값과 기대값을 남긴다. 배열 출력은 lane도 식별한다.
- **사용자 확정: 기본 로그는 불일치 상세와 최종 요약으로 한다.** 최종 요약에는 검사 수·오류 수와 PASS/FAIL을 남긴다. 정상 일치한 벡터의 값을 매번 출력하지 않는다.
- 생성 설정과 데이터 출처, 실행 도구·결과를 재현할 수 있게 기록한다. 실제 파일 위치와 실행 명령은 구현 시 정한다.

### 불일치 처리와 개별 모듈 실행

- **사용자 확정: 첫 불일치에서 해당 모듈의 실행을 중단한다.** 모듈명, 벡터 번호·시점, 신호명, 실제값·기대값을 기록하고 FAIL로 남긴다. 배열 출력은 lane도 식별한다.
- **사용자 확정: 실패 확인 후 어떤 모듈을 실행할지는 사용자가 직접 판단한다.** 실행 스크립트는 실패한 모듈에서 다른 모듈로 자동 이동하지 않는다.
- 검증하고 싶은 모듈만 직접 실행하고, 건너뛸 모듈은 실행하지 않는 방식으로 모듈 단위 선택·제외를 수행한다. 개별 테스트 케이스 선택·제외와 전체 모듈 일괄 실행은 현재 지원 범위에 포함하지 않는다.
- 다른 모듈을 실행하더라도 기존 실패 기록은 FAIL로 유지한다. 실행하지 않은 모듈을 검증 완료나 PASS로 처리하지 않는다.
- 기대값 변경이나 비교 마스크 확대로 불일치를 숨기지 않는다. 선택한 모듈에서는 정의된 출력을 계속 비교한다.

컴파일·계층 전개 통과와 기능 검증 PASS를 구분한다. 하위 연산기 미구현 상태의 첫 xsim 실행은 X 불일치로 FAIL이었고, 구현 후 실제 MAC 단독 타깃은 준비한 전체 비교를 완료해 PASS했다. 기존 FAIL 기록은 유지한다. 이 결과는 이미지 0번 정상 흐름을 재현한 MAC 단독 검증이며 실제 MAC을 연결한 Top 통합 검증 결과는 아니다.

## 8. 남은 구체화

- 생성기의 별도 테스트 및 전체 실제 RTL을 연결한 Top 통합 검증.
- 하위 모듈 개별 TB의 범위와 parameter 조합. 정상 추론 밖의 추가 사례나 개별 연산기의 범위 밖 입력·오버플로 동작은 이번에 확정하지 않는다.
- 실제 RTL 구현·실행·검증은 별도 요청에 따라 단계별로 진행한다.

공통 실행기는 `90_scripts/run.py`이며 `90_scripts/sim_targets.json`의 `mac_array` 타깃으로 실제 MAC 단독 기능 검증을 통과했다. Top 타깃의 MAC도 실제 RTL로 교체한 뒤 `07_runs/mlp_top_xsim_20261109_144425_513778Z/`에서 컴파일·계층 전개·xsim을 통과했다. 전체 265,015개 벡터·913,467회 비교에서 오류 0, prediction 7이다. 누산기·후처리만 임시 모델로 남는다.

미정 동작은 기대값을 임의로 확정해 생성하지 않는다. 해당 사항을 정한 뒤 생성기와 tester에 함께 반영한다.
