## 1. 역할

| 모듈 | 담당 기능 |
| --- | --- |
| Memory wrapper | 가중치·bias·입출력 BRAM |

## 3. BRAM 구성과 데이터 배치

### 3.1. 공통 규칙

연산에 필요한 데이터는 내부 BRAM에 저장한다. **우선 메모리 IP를 사용하지 않고 SystemVerilog의 동기식 읽기·쓰기로 기술해 Vivado의 BRAM 자동 추론을 사용**한다. 실제 BRAM 매핑은 합성 보고서로 확인하고 필요하면 추후 Memory wrapper 내부를 IP 구현으로 교체한다. **입출력 버퍼 A/B, 가중치 4개 bank, bias 메모리 모두 single-port BRAM**으로 구성한다. 각 메모리는 한 클럭에 읽기 또는 쓰기 하나를 수행한다. 모든 메모리의 읽기 지연은 **1클럭**으로 구성한다. 쓰기는 유효 클럭 에지에서 32비트 한 워드를 기록하는 동기식 쓰기를 사용한다. 결과 준비와 쓰기 전후 제어에 필요한 사이클은 메모리의 기록 동작과 구분한다.

입력·출력·weight·bias 모두 32비트 워드에 8비트 데이터 4개를 같은 순서로 배치한다.

| 비트 위치 | 데이터 순서 |
| --- | --- |
| [7:0] | 첫 번째 |
| [15:8] | 두 번째 |
| [23:16] | 세 번째 |
| [31:24] | 네 번째 |

동일한 메모리에서 읽기와 쓰기를 동시에 수행하지 않는다. TB의 외부 접근과 내부 추론 접근도 동시에 사용하지 않으며, 선택 기준은 Reset, 초기화 및 실행 제어과 같다.

메모리의 논리 깊이는 다음과 같이 확정한다. 실제 BRAM 블록 배치와 사용량은 Vivado 매핑 결과로 확인한다.

| 메모리 | 폭 | 논리 깊이 |
| --- | ---: | ---: |
| 버퍼 A | 32비트 | 196워드 |
| 버퍼 B | 32비트 | 128워드 |
| 가중치 bank 0~3 | 각각 32비트 | 각각 29,280워드 |
| Bias | 32비트 | 163워드 |

### 3.2. 입출력 핑퐁 버퍼

입출력 버퍼 A와 B는 각각 **32비트 폭**이다. 출력 메모리가 다음 레이어의 입력 메모리가 되고, 이전 입력 메모리는 다음 출력 메모리로 재사용된다.

| 연산 | 입력 메모리 | 출력 메모리 |
| --- | --- | --- |
| FC1 | A: 이미지 784개 | B: FC1 결과 512개 |
| FC2 | B: FC1 결과 512개 | A: FC2 결과 128개 |
| FC3 | A: FC2 결과 128개 | B: 실제 결과 10개 + 더미 2개 |

출력 4개는 병렬 후처리한 뒤 32비트 한 워드로 묶어 저장한다. 같은 버퍼를 동시에 읽고 쓰지 않는다. 레이어가 바뀔 때 버퍼 역할 전환을 위한 대기 사이클은 허용한다. 논리 깊이는 A 196워드, B 128워드다. Memory wrapper 내부에서 버퍼 역할을 선택한다.

Memory wrapper는 내부 입력 읽기 포트와 출력 쓰기 포트를 제공한다. Control unit의 선택 비트에 따라 A/B를 연결한다.

| 버퍼 선택 | 입력 읽기 | 출력 쓰기 |
| ---: | --- | --- |
| 0 | A | B |
| 1 | B | A |

입력 읽기에는 주소와 enable, 출력 쓰기에는 주소·enable·32비트 데이터를 전달한다. 내부 입력 읽기 주소는 8비트 워드 주소, 출력 쓰기 주소는 7비트 워드 주소다.

### 3.3. 가중치 bank

가중치는 **32비트 폭 메모리 4개를 bank로 사용**한다. 가중치 메모리는 초기화 후 추론 중에는 읽기 전용으로 사용한다. 한 주소에서 bank마다 가중치 4개를 읽으므로, 총 16개를 공급한다.

| Bank | 가중치를 공급받는 출력 그룹 |
| --- | --- |
| 0 | 그룹 0 |
| 1 | 그룹 1 |
| 2 | 그룹 2 |
| 3 | 그룹 3 |

추론용 읽기 주소는 **15비트 워드 주소 1개**를 4개 bank가 공유하며, 읽기 enable도 공통 1개를 사용한다. 각 bank의 32비트 읽기 데이터로 총 16개 가중치를 전달한다.

각 bank에는 **FC1 → FC2 → FC3** 영역을 연속 배치한다. 레이어가 바뀌면 해당 영역의 시작 주소부터 읽는다.

레이어 내부에서는 **출력 묶음 우선 순서**를 사용한다. 출력 4개를 고정한 채 전체 입력을 4개씩 처리하고, 다음 출력 묶음으로 넘어간다. 가중치 주소는 연속 증가하고 입력 주소는 출력 묶음이 바뀔 때 처음으로 돌아간다.

FC1 영역 시작 기준의 상대 주소 예시는 다음과 같다.

| 상대 워드 주소 | 계산 중인 출력 | 사용하는 입력 |
| --- | --- | --- |
| 0 | 0~3 | 0~3 |
| 1 | 0~3 | 4~7 |
| 195 | 0~3 | 780~783 |
| 196 | 4~7 | 0~3 |
| 197 | 4~7 | 4~7 |
| 25,087 | 508~511 | 780~783 |

이 배치의 레이어별 논리 저장량은 다음과 같다. 각 bank의 전체 논리 깊이는 합계인 29,280워드다.

| 레이어 | 출력 묶음 수 | 묶음당 입력 워드 수 | Bank당 가중치 워드 수 |
| --- | ---: | ---: | ---: |
| FC1 | 128 | 196 | 25,088 |
| FC2 | 32 | 128 | 4,096 |
| FC3 (더미 포함) | 3 | 32 | 96 |
| 합계 | — | — | 29,280 |

### 3.4. Bias 메모리

Bias 4개를 한 워드에 묶는 **32비트 폭, 총 163워드** 구성이다. Bias 메모리도 초기화 후 추론 중에는 읽기 전용으로 사용한다. 한 번 읽은 bias 4개를 각 누산기의 초기화에 사용한다. 내부 bias 읽기 주소는 8비트 워드 주소다. Bias 정렬량은 Control unit에서 전달하며, 부호 확장과 정렬은 누산기·후처리 모듈에서 수행한다.

### 3.5. FC3 더미 출력

FC3의 출력 10개를 4개씩 처리하기 위해 더미 출력 2개를 추가한다. 두 더미의 모든 가중치와 bias는 0으로 저장한다.

```text
첫 묶음: 출력 0~3
둘째 묶음: 출력 4~7
셋째 묶음: 출력 8, 출력 9, 더미 0, 더미 0
```

마지막도 32비트로 저장하며, 최종 결과에서는 앞의 10개만 사용한다.

### 3.6. 레이어별 시작 주소

Bias도 FC1 → FC2 → FC3 순서로 연속 배치한다. 아래 값들을 Control unit의 설정 LUT에 넣는다.

| 레이어 | 각 가중치 bank의 시작 워드 주소 | Bias 시작 워드 주소 |
| --- | ---: | ---: |
| FC1 | 0 | 0 |
| FC2 | 25,088 | 128 |
| FC3 | 29,184 | 160 |

내부 주소는 32비트 한 워드를 단위로 한다. 외부 바이트 주소는 해당 메모리 시작 바이트 주소 + 내부 워드 주소 × 4다.

## 4. 추론용 주소의 유효 조건

| 주소 출력 | 주소가 유효한 조건 |
| --- | --- |
| `in_addr` | `in_en = 1` |
| `weight_addr` | `weight_en = 1` |
| `bias_addr` | `bias_en = 1` |
| `out_addr` | `out_we = 1` |

대응하는 enable이 0일 때의 주소값은 제한하지 않는다. 주소를 0으로 출력하거나 이전 값으로 유지할 의무는 없다.

## 5. TB 외부 메모리 접근

추론 제어와 분리된 TB 초기화·검증용 메모리 접근 인터페이스를 Top에 둔다. 해당 포트의 접두사는 tb로 통일한다.

| 신호 | 방향 | 폭 |
| --- | --- | ---: |
| tb_addr | TB → Top | 20비트 |
| tb_wdata | TB → Top | 32비트 |
| tb_rdata | Top → TB | 32비트 |
| tb_en | TB → Top | 1비트 |
| tb_we | TB → Top | 1비트 |

쓰기 데이터 입력과 읽기 데이터 출력은 분리한다. 각 데이터 경로는 버퍼 A/B, 가중치 4개 bank, bias 메모리가 공유한다. 하나의 32비트 양방향 데이터 포트는 사용하지 않는다. 메모리 선택은 주소에 포함한다.

| Enable | Write enable | 요청 동작 |
| ---: | ---: | --- |
| 0 | 무관 | 접근 없음 |
| 1 | 0 | 지정 주소의 32비트 읽기 |
| 1 | 1 | 지정 주소에 32비트 쓰기 |

외부 읽기도 요청 후 1클럭 지연으로 데이터를 받는다.

접근 경로는 다음 기준으로 구분한다.

| busy | 메모리 접근 경로 |
| ---: | --- |
| 0 | TB가 외부 초기화·검증용 포트 사용 가능 |
| 1 | 내부 추론 경로 사용. 외부 포트는 사용하지 않음 |

가중치·bias의 초기화 쓰기는 이 외부 경로로 수행하며, 추론 경로에서는 읽기만 한다. 향후 FPGA용 구성에서 외부 접근 포트를 제거하기 쉽게 분리한다. 포트 제거 후 가중치·bias 초기값을 공급하는 방법은 추후 정한다.

## 6. 외부 주소 해석

외부 주소는 **20비트 바이트 주소**다. 접근은 **4바이트 정렬 주소에서 32비트 단위**로 수행한다. 개별 바이트 접근과 비정렬 접근은 지원하지 않는다.

```text
주소 [19:17] : 메모리 선택
주소 [16:2]  : 선택한 메모리의 BRAM 워드 주소
주소 [1:0]   : 00 (4바이트 정렬)
```

가중치 bank 하나의 논리 저장량은 29,280워드 = 117,120바이트이므로 바이트 오프셋에 17비트가 필요하다. 메모리 선택 3비트와 합쳐 외부 주소 폭을 20비트로 정했다.

| 주소 [19:17] | 대상 메모리 | 시작 바이트 주소 |
| --- | --- | --- |
| 000 | 버퍼 A | 0x00000 |
| 001 | 버퍼 B | 0x20000 |
| 010 | Weight bank 0 | 0x40000 |
| 011 | Weight bank 1 | 0x60000 |
| 100 | Weight bank 2 | 0x80000 |
| 101 | Weight bank 3 | 0xA0000 |
| 110 | Bias | 0xC0000 |
| 111 | 미사용 | 0xE0000 |

각 영역은 주소 공간상 128 KiB 간격으로 배정한다. 메모리별 논리 깊이는 공통 규칙과 같으며, 주소 영역 전체를 실제 저장 공간으로 할당하는 것은 아니다.

메모리 시작 주소 기준의 바이트 오프셋은 저장된 8비트 데이터의 인덱스에 대응한다.

| 바이트 오프셋 | 한 번에 접근하는 데이터 |
| ---: | --- |
| 0 | 데이터 0~3 |
| 4 | 데이터 4~7 |
| 8 | 데이터 8~11 |

BRAM 내부 워드 주소는 해당 영역의 바이트 오프셋을 4로 나눈 값이다. 가중치의 데이터 인덱스는 원본 행렬을 단순히 펼친 순서가 아니라, 메모리 구성과 데이터 배치에서 정한 bank별 저장 순서를 기준으로 한다.

## 7. TB 입력 조건과 응답 유효 구간

TB는 정상 주소만 입력한다. 정상 주소는 사용 중인 메모리 영역을 선택하고, 해당 메모리의 논리 깊이 이내이며, `tb_addr[1:0] = 2'b00`인 주소다. 미사용 영역, 범위 밖 주소, 비정렬 주소의 처리 동작은 정의하지 않는다.

`start`를 주는 클럭에는 `tb_en = 0`으로 두며, 추론 시작 요청과 TB 메모리 접근을 동시에 요청하지 않는다.

TB 메모리 접근은 `busy = 0`일 때만 사용한다. `busy = 1`이면 내부 추론 경로를 사용한다.

`tb_rdata`는 TB 읽기 요청에 대한 1클럭 지연 응답에서만 유효하다. 나머지 구간의 출력값은 보장하지 않는다. 각 BRAM의 읽기 출력 레지스터가 값을 유지하는 규칙과 외부 `tb_rdata`의 유효 조건은 구분한다.

## 8. 읽기·쓰기와 출력 유지

각 BRAM의 읽기 출력 레지스터는 다음 규칙을 따른다.

| Reset이 비활성일 때의 조건 | 저장 내용 | 읽기 출력 레지스터 |
| --- | --- | --- |
| `en = 0` | 유지 | 이전 읽기 값 유지 |
| `en = 1`, `we = 0` | 유지 | 지정 주소의 읽기 값으로 갱신 |
| `en = 1`, `we = 1` | 지정 주소에 32비트 워드 기록 | 이전 읽기 값 유지 |

읽기 주소와 enable은 상승 에지 R에서 샘플링하고, 읽기 데이터는 R 직후 갱신된다. 이 데이터를 다른 모듈의 레지스터가 샘플링하는 시점은 다음 상승 에지 R+1이다.

읽기와 쓰기를 한 BRAM에서 같은 클럭에 동시에 수행하지 않는다. 쓰기 시 읽기 출력을 새 쓰기 데이터로 갱신하지 않는다.

ARGMAX가 한 워드의 여러 바이트를 처리하는 동안에도 읽기 출력의 이전 값을 유지한다.

## 9. 실행 전 데이터 초기화

1. TB가 Top의 초기화·검증용 메모리 접근 포트를 통해 가중치·입력 이미지 한 장·bias·기타 필요한 데이터를 기록한다.
2. 필요한 데이터의 초기화를 모두 완료한다.
3. TB가 1클럭 길이의 `start` 펄스를 주어 추론을 시작한다.
4. `done`을 확인한 뒤 동일한 메모리 접근 포트로 최종 결과를 읽는다.

TB가 계층 경로로 내부 BRAM 내용을 직접 읽고 쓰는 방식을 외부 접근 인터페이스로 사용하지 않는다.

## 10. 연산 경로와의 클럭 관계

아래 에지는 상승 에지다. R은 주소와 enable을 BRAM이 샘플링하는 읽기 에지이며, BRAM 읽기 데이터는 R 직후 갱신된다. 다음 에지 R+1에서 곱셈 결과를 레지스터에 저장한다.

| 읽기 수행 에지 기준 | 동작 |
| --- | --- |
| R | 입력·가중치 BRAM 읽기 |
| R+1 | input_valid = 1로 곱셈 결과와 유효 표시 1단 저장 |
| R+2 | Adder tree 부분합과 psum_valid 갱신 |
| R+3 | psum_valid를 샘플링해 해당 부분합 누산 |
| R+4 | 출력 묶음의 마지막 읽기였다면 완료된 누산값을 결과 레지스터에 저장 |
| R+5 | 출력 묶음의 마지막 읽기였다면 후처리한 출력 4개를 BRAM에 기록 |

R+5의 출력 쓰기 주소는 R에서 읽기와 함께 보관한 출력 묶음 번호를 지연시켜 사용한다.

현재 묶음의 마지막 누산이 끝난 뒤, 결과 레지스터 저장과 다음 묶음의 bias 초기화를 같은 에지에 수행한다. 마지막 출력 묶음에서는 다음 bias 초기화를 수행하지 않는다. Bias 초기화와 부분합 누산은 겹치지 않는다.

## 11. 레이어 전환 시점

Start를 받아들이는 상승 에지를 S라고 하면 다음 일정을 사용한다.

| 에지 | 동작 |
| --- | --- |
| S | start 수락, busy = 1 |
| S+1 | PREP에서 FC1 설정과 버퍼 역할 준비 |
| S+2 | 첫 입력·가중치·bias 읽기 시작 |

FC1→FC2 및 FC2→FC3의 전환에서도 같은 준비 흐름을 사용한다. 이전 레이어의 마지막 출력 저장 에지를 L이라고 하면 다음과 같다.

| 에지 | 동작 |
| --- | --- |
| L | 이전 레이어 마지막 출력 워드 저장 |
| L+1 | PREP에서 다음 레이어 설정과 A/B 역할 전환 |
| L+2 | 다음 레이어 첫 입력·가중치·bias 읽기 |
| L+3 | Bias 초기화 및 첫 곱셈 결과 저장 |
| L+4 | 첫 부분합 저장 |
| L+5 | 첫 부분합 누산 |

후처리 설정은 이전 레이어의 마지막 저장이 끝난 뒤 변경한다. 레이어 전환 때 전체 reset을 다시 주지 않는다. Control unit이 새 입력의 input_valid 시점을 맞추고, MAC에서 전달된 psum_valid가 유효할 때만 누산한다.

## 12. Reset

모든 읽기·쓰기는 클럭 상승 에지 기준이다. `rst_n`은 비동기 active-low reset이다.

`rst_n = 0`이면 BRAM 저장 내용을 제외한 모든 레지스터를 클럭 에지를 기다리지 않고 0으로 초기화한다. 메모리 읽기 출력 레지스터도 포함한다.

BRAM 저장 내용은 reset으로 지우지 않으며, 모든 주소를 순회하는 초기화 회로도 만들지 않는다.

TB는 reset 중 `start = 0`, `tb_en = 0`을 보장한다.

## 14. 구현·검증 상태

`04_rtl/memory/`의 하위 모듈 5개에 동작을 작성했다. 외부 포트·메모리 깊이·기존 상위 배선은 유지한다.

- `tb_address_decoder`: 메모리 선택·워드 주소 분리와 TB enable의 메모리별 전달.
- `memory_port_mux`: `busy`에 따른 TB/내부 접근 선택.
- `buffer_router`: A/B의 입력 읽기·출력 쓰기 배정과 읽기 출력의 조합 선택.
- `single_port_bram`: 상승 에지 쓰기·1클럭 읽기, 쓰기·비활성 시 읽기 출력 유지. 저장 배열은 reset하지 않고 읽기 출력만 비동기로 0 초기화.
- `tb_read_mux`: 읽기 요청 시 메모리 선택만 레지스터에 저장하고 BRAM 읽기 출력을 조합 선택. 추가 데이터 레지스터 없음.

실제 Memory RTL로 컴파일·계층 전개 및 이미지 0번의 단독 xsim 검증을 통과했다. 265,015개 벡터·1,708,021회 비교에서 오류 0이며, 실행 기록은 `07_runs/memory_wrapper_xsim_20261109_103936_500210Z/`에 보존했다. 기존 golden·TB·tester·비교 마스크는 변경하지 않았다.

실제 Top·Control·Memory에 MAC·누산기 임시 모델을 연결한 Top 검증도 통과했다. 265,015개 벡터·913,467회 비교에서 오류 0, 최종 prediction은 7이며 실행 기록은 `07_runs/mlp_top_xsim_20261109_104742_239167Z/`에 보존했다. 전체 실제 RTL 통합 검증 및 실제 BRAM 추론·자원 매핑·타이밍 확인은 남아 있다. 미사용·범위 밖·비정렬 주소의 동작은 여전히 정의하지 않는다.
