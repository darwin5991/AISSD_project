# MAC 입력 레지스터 추가 명세 (2026-11-10)

사용자 결정에 따라 MAC 입력과 곱셈기 사이에 입력·가중치 레지스터 1단을 추가한다.
현재는 **3단 MAC·Control RTL과 검증환경 코드 수정까지 완료**한 상태다.
새 검증 데이터·헤더 5종은 [별도 생성 기록](../07_runs/mlp_mac3_verification_data_20261110_062259_518805Z/README.md)에
보존했다. 생성기 내부 검사는 PASS했지만 단위 테스트·새 RTL 기능 시뮬레이션·합성·배치배선은
아직 실행하지 않았다. 이번 단계에서는 코드만 수정했으며 데이터 재생성·실행·커밋은 하지 않았다.

## 1. 데이터·valid 구조

```text
BRAM 읽기 출력 (기존 1클럭 응답)
  -> Top의 조합 워드 분리
  -> MAC 내부 signed INT8 입력 4개 + 가중치 16개 레지스터 [신규 1단]
  -> signed 곱셈 -> 32비트 곱 결과 레지스터             [2단]
  -> 두 레벨 adder tree -> 32비트 부분합 레지스터       [3단]
  -> partial_sum
input_valid -> valid 1단 -> valid 2단 -> valid 3단 -> psum_valid
```

공통 입력 4개는 등록 후에도 네 lane에 공통으로 전달한다. 입력·가중치의 비트 폭,
lane 순서, 곱의 32비트 부호 확장, 두 덧셈 레벨과 누산 수치 규칙은 유지한다.
Adder tree 앞·뒤의 기존 레지스터를 유지하고 트리 내부 레지스터는 추가하지 않는다. 기존 dot_product4의 곱 결과·부분합 2단 앞에 MAC 입력단 1단을 더해 전체 MAC이 3단이 된다.
모든 MAC 데이터·valid 단계는 매 클럭 갱신하며, invalid 입력도 같은 지연으로 전달한다.
새 레지스터는 기존 비동기 active-low reset 규칙대로 0 초기화한다. 추가 구현 모듈명과
물리적인 레지스터 복제·배치는 구현 단계에서 구체화하되 이 논리적 동작을 지킨다.

## 2. 읽기 에지 R 기준 일정

| 에지 | 동작 |
| --- | --- |
| R | 입력·가중치 BRAM 읽기 |
| R+1 | MAC 입력·가중치와 valid 1단 저장 |
| R+2 | 곱 결과와 valid 2단 저장 |
| R+3 | 부분합과 valid 3단/psum_valid 갱신 |
| R+4 | 부분합 누산 |
| R+5 | 묶음 마지막 입력이면 결과 저장 및 다음 묶음 bias 적재 |
| R+6 | 묶음 마지막 입력이면 후처리 결과를 출력 BRAM에 기록 |

기존 BRAM/TB 읽기 응답은 1클럭, 입력 읽기 간격과 묶음 사이 공백은 1클럭으로 유지한다.
`mac_input_valid`도 읽기 여부의 1클럭 지연을 유지한다. 레이어 첫 bias 적재는 기존대로
첫 bias 읽기 다음 에지에 수행한다. 누산이 시작되기 전에 bias가 적재되어 있으므로
첫 bias 적재를 추가로 지연하지 않는다. 후속 묶음 bias 적재는 이전 결과 저장과 함께
R+5로 한 클럭 늦추고, bias 적재와 유효 부분합 누산이 겹치지 않게 한다.
`result_load`는 마지막 읽기+5, `out_we`·`out_addr`·`layer_stored`는 마지막 읽기+6에 맞춘다.
결과 저장은 같은 에지의 새 누산값이 아니라 에지 직전 완료값을 사용한다.

마지막 출력 저장 L 이후 다음 레이어 준비 L+1, 첫 읽기 L+2는 유지한다.
새 레이어의 bias 적재·입력 등록은 L+3, 곱 결과 L+4, 부분합 L+5, 첫 누산 L+6이다.
FC3 완료 후 ARGMAX 첫 읽기도 L+2를 유지하고 ARGMAX 내부 1클럭 읽기 일정은 바꾸지 않는다.
각 레이어의 마지막 저장은 해당 레이어의 이전 일정 대비 1클럭 증가하므로 전체 추론은
3개 레이어 합계 3클럭 길어진다. 묶음마다 공백을 추가하는 변경은 아니다.

## 4. 구현 및 검증 문서의 적용 범위

- Architecture와 MAC·Control·Memory·누산기·Top 명세의 동일 일정 표를 함께 갱신했다.
- 새 입력단은 MAC 내부에 두며 Top 외부 포트나 BRAM 읽기 지연은 변경하지 않는다.
- MAC 입력 4개·가중치 16개를 기존 register_en으로 등록하고 valid 지연을 3단으로 수정했다.
- Control의 결과 저장·후속 bias 적재는 5단, 출력 쓰기·주소·레이어 완료는 6단으로 수정했다.
  첫 bias와 mac_input_valid의 1단 지연은 유지했다. 내부 next_bias_d4는 next_bias_d5로 맞췄다.
- 모듈별 golden과 Top 기준 흐름, tester·공통 실행기의 길이/지연 검사 코드를 함께 수정했다.
  생성 헤더 5종은 별도 생성 단계에서 갱신했다. 이전 헤더는 새 실행기·tester의 사전 검사에서 거부한다.
- 원본 이미지·weight·bias·부분합·누산·레이어 출력 정답의 수치와 배열 순서는 유지한다.
  클럭별 벡터는 새 일정으로 생성했다. 원본 모델 추론을 다시 수행하는 변경은 아니다.
- 각 모듈의 기존 비교 범위·마스크·이미지 선택·오류 처리 정책은 유지한다.
- 기존 `07_runs/`와 소스 snapshot, 생성 데이터, checkpoint는 변경하지 않는다.
  기존 기능 PASS와 setup FAIL은 이전 2단 구조의 결과이며 새 명세의 검증 근거가 아니다.
- OOC 클럭 출발 위치·입출력 제약·BRAM 비동기 제어 DRC 경고는 아직 별도 과제로 남아 있다.
  새 입력단이 이 조건까지 해결했다고 가정하지 않는다. LUT/DSP 선택 방침도 유지한다.

진행 상태는 문서·검증환경·실제 RTL 코드 수정 완료, 데이터 생성 및 생성기 내부 검사 PASS다.
다음은 별도 요청에 따른 단위 테스트·기능 검증이며, 그 뒤 합성·배치배선도 별도로 요청받아
진행한다. 코드 수정과 실행을 같은 단계에서 자동으로 진행하지 않는다.

MAC 생성기의 헤더·README·vector_contract 설명에 남아 있던 k+2 표기는 k+3으로 수정했다.
이미 생성·커밋한 헤더와 실행 기록은 수동 편집하거나 재생성하지 않았다. 해당 데이터의 실제
PIPELINE_DEPTH는 3이고, 설명 불일치는 기존 생성 기록의 알려진 문제로 보존한다.
