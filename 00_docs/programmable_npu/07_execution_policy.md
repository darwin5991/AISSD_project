# Execution policy — unattended local Codex
User authorizes local implementation, simulation, Vivado synthesis/implementation, power, and Git commits. No remote push or external modifications. Follow AGENTS and normative spec. Continue through all gates without asking for ordinary decisions. Environment/permissions are not guaranteed; never bypass organizational security controls.

## Preflight and Git
- Windows 11 local VS Code Codex extension, existing native Windows Python/Vivado. Discover executable paths and current usable Python, don't reinstall tools or globally modify PATH/settings without need. Use repo-local environment if necessary; no automatic network downloads or uploading data. Use batch mode, no GUI prompts. Check `git status --short --branch`, `git rev-parse HEAD`, `git branch`, baseline commit object and existing local files. Preserve user's uncommitted edits (including ignored model/data). Never `reset --hard`, `clean -fdx`, stash/pop user work or silently overwrite it. If checkout conflicts, stop before destructive operation; alternative isolated local worktree may be used if model/dataset are accessible via explicit local path and files not copied unnecessarily. Do not start from Phase8.
- If user has already created branch from pinned main and copied docs, continue it; otherwise `git switch -c npu-v2/<timestamp> 2e89b8e994982094a36172a3fd2f65d4a9edaff7` (only if safe). Initial docs commit on new branch. Record exact SHA and branch. Do not change main or remote refs. Do not push, open PR, force-push, delete existing branches, rewrite history or merge into main. Avoid network/remote commands. Stage explicit tracked/new source files, not large logs, checkpoint/dataset, generated binaries, credentials, or environment config. Use `git diff --check`, review staged diff, tests then commit e.g. `npu: M3 DMA and SRAM transfer gate`. Keep build dirs ignored (check existing .gitignore, extend carefully).
- A gate commit records actual tests, commit used for run, status and artifact location. Record pre-commit source diff/hash when test precedes commit; final report associates evidence with exact RTL source version (documentation-only commits may follow).

## Decisions and recovery
1. If clear spec, implement as specified. If unspecified detail, inspect baseline, choose simplest compliant option; record options, evidence, why, affected files, anchor SHA and regression test in 08 before making change. Do not ask user unless no safe compliant route exists. Never modify normative docs to redefine acceptance; clarify implementation-only details in decision log.
2. On failure, capture failing command, exact output, run dir, git status/SHA, sample IDs and comparison. Diagnose first (data, codegen, assembler, simulator, RTL, constraints) before changing; make focused fix and rerun affected gate plus regressions. Do not rerun identical failure without new hypothesis. Keep failure evidence; don't change expected values or suppress warnings to pass.
3. Default bounded policy (selected operational limit): at most **3 substantive repair attempts per blocker** on a branch. If no meaningful new evidence or repeated identical error twice, stop same-path retries early. If a documented alternative is plausible, preserve failing branch (commit clearly marked `WIP/FAIL` only after diff review and never as PASS), create new recovery branch from last good commit before relevant decision, e.g. `npu-v2/recovery-01`; keep docs available from initial docs commit, copy necessary decision/progress records deliberately and document ancestry. No hard reset or history loss. Reapply only needed verified changes. Max **2 recovery branches total** per unattended run, each subject to 3 repair attempts per blocker; max 12 substantive repair attempts across the run as additional hard cap. Do not start random alternatives without a reason. Recover from commit before problematic choice, not entire project unless justified. If exhausted, preserve exact failure and stop; report branch/commit and proposed next step. Do not create branch on every small bug. On timeout/licensing/model absence or permissions block, try existing available paths once, then report; don't bypass or fabricate.
4. Avoid long unattended loops: set per-command watchdog timeout appropriate to scenario (e.g. derive simulated cycle limit from model read count with margin; XSim and Vivado wall timeout configurable). If timeout, terminate only owned process/job, retain logs and diagnose. Do not kill unrelated user processes. No arbitrary wall clock benchmark for inference. Budget: stop before resource exhaustion; no unbounded repeated runs. If context compaction occurs, re-read 08/09 and continue from last passing gate; do not restart completed work blindly.

## Reporting and handoff
Update 09 after each milestone, log commands/exit codes, artifact hashes/paths, actual results. If partial, explicitly distinguish pass/fail/not run. 10 final report must include source version, exact local branch/commit, original base, decision/recovery ancestry, commands, unit and scenario results, first mismatch if any, resources, setup/hold, unconstrained scope, power assumptions, limitations, next user commands. If all required gates pass, finish with no further optional experiments. No push at any time.
